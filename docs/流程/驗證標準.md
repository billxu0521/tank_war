來源：<https://github.com/RemakeBench/skills>（MIT）
2026-09-11 裝到這台機器上：`remakebench-skills@remakebench` v0.3.0，user scope。

```
claude plugin marketplace add RemakeBench/skills
claude plugin install remakebench-skills@remakebench
```

這套技能是[那部 60 小時做遊戲的影片](../技術筆記/AI輔助遊戲開發.md)的方法論，做成 Claude Code
可以自動載入的規則。作者的立場是：每條規則都對應一個真實發生過的失敗。

## 八個技能

| 技能 | 管什麼 |
|---|---|
| `verify-by-playing` | **遊戲的驗收閘門**。要用真輸入玩過，不接受「測試全綠」 |
| `game-production-stages` | 先有可玩的佔位沙盒，才做正式資產；每個階段有證據支撐的出口條件 |
| `reference-pack-authority` | 概念美術要先有書面的空間真實來源，才開始做幾何 |
| `image-to-3d-modular-kit` | image-to-3D 要拆成獨立模組、前後左右各自一張圖 |
| `3d-asset-quality` | 資產要有厚度、倒角、合理構造，並用只有幾何的驗收渲染證明 |
| `asset-judge-loop` | 批次資產要用獨立評審、取最低分、盤點對帳、重建循環 |
| `codex-subagent` | 把審查外包給 OpenAI Codex，拿獨立第二意見 |
| `grok-subagent` | 同上，改用 xAI Grok |

## `verify-by-playing`：對本專案最直接的一個

它的論據是某專案在**測試全綠**的情況下依序出貨了：失效的鍵盤、被自己碰撞體封死的
關卡、被搶走的相機、爬不上去的樓梯、不會生效的死亡特效。每一個都是人去玩才發現的。

它要求五項證明，而且都要對**跑起來的實際版本**做：

1. **真輸入** — 走平台真正的輸入路徑，不是直接設速度
2. **走完路線** — 從出生點走到目標，過每一道門、每一段階梯，用座標確認到達
3. **相機歸屬** — 確認畫面是遊戲相機在渲染，沒有截圖用的相機被留著開
4. **每個動作都量測** — 「動畫在播」不算，「揮 1 次、命中 1 次、血 2→1」才算
5. **看截圖** — 數字證明機制，只有畫面看得出劍拿反了、特效沒出來

### 這條打到我

> 由建造它的那個 agent 宣稱「已截圖檢查」，依定義就是未驗證。

**這整個專案我都是這樣做的**——我改完、我自己截圖、我自己看、我說可以了。
我知道自己想看到什麼，所以我看得到我想看的。

而且我們踩過的坑幾乎都在它的清單上，**每一個發生時測試都是綠的**：

| 我們踩過的 | 怎麼發現的 |
|---|---|
| 相機朝天（row-major 寫成 column-major）| 截圖只看到天空 |
| 砲管朝後、太陽朝上 | 同上，同一個原因 |
| 恐龍爬不上牆 | 跑起來量高度 |
| 跳躍被貼地邏輯吃掉 | 跑起來量高度 |
| bot 開過撤離區、進度一直歸零 | 想到才去補，不是測出來的 |
| 一進遊戲砲塔自己甩到隨機角度 | 截圖時發現砲管方向不對 |
| 移動時的殘影（物理 60Hz vs 畫面 120fps）| 使用者反映 |

## 實際要改什麼

**做得到的：**

- 驗證改成「會不會變紅」——新的檢查先故意弄壞一次，確認它抓得到。
  這個本專案做過一次（測試失敗卻照印 OK，那次是真的抓到問題）
- 量測取代狀態——本專案的模擬器已經是這個路線（印勝率、死因、局長，
  不是印「有跑完」）
- 走完實際路線——例如恐龍爬牆那次，量的是「爬到幾公尺、體力剩多少」，符合

**做不到、要誠實承認的：**

- **獨立驗證**。我沒辦法自己當「沒參與建造的一方」。
  現成的解是 `codex-subagent` / `grok-subagent`，但那要裝外部 CLI、登入、**消耗付費額度**。
  在還沒決定要不要花那筆錢之前，我的截圖檢查就只能標成「未獨立驗證」。

**暫時用不上的：** 四個 3D 資產產線技能。本專案是灰盒，暴龍是
[程式建骨架](../技術筆記/程序化動畫.md)，沒有 image-to-3D 也沒有資產批次。
哪天要把灰盒換成真模型，那四個才會啟用。
