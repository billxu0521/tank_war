# 場景編輯工具規劃：程式先自動擺，人最後微調

## 目標

現在整個場地是「每次開遊戲，用固定種子的亂數自動擺」（`main.gd` 的 `_build_arena`）。好處是不用手擺，
壞處是**想把某棵樹挪兩公尺、刪掉一堆箱子、在某處加一座風車，只能改程式碼、而且會連動其他東西的位置**。

要的是：**自動擺出初稿 → 存成一個場景檔 → 人在編輯器裡拖、轉、刪、加 → 遊戲照這個檔蓋出來**。
所有機器讀同一個檔，連線不用額外同步。

## 現況（要拆開的地方）

- 「決定擺在哪」和「把東西蓋出來」寫在同一個函式裡（例如 `_barn` 同時算位置、蓋碰撞、放門和梯子、擺雜物）
- 很多規則靠「擺好之後記下來的位置」：出生點避開建築（`_blocked`）、撤離區淨空（`_reserved`）、
  bot 判斷人躲在灌木裡（`_bushes`）、麥田地面上色（`_wheat_fields`）、地形在建築下整平（`flatten_circle`）
- 為了「不動到後面東西的位置」，程式裡有很多「亂數照樣抽掉」的繞路寫法——手調之後這些都不需要了

## 建議做法：烘成場景檔，用 Godot 編輯器調

Godot 編輯器本身就是完整的場景編輯器（選取、移動、旋轉手把、複製、刪除、復原、多選），不用自己再做一套。

1. **擺設清單化**：把 `_build_arena` 拆成兩步——先產生一份「擺設清單」（每一項：種類、位置、朝向、大小、額外參數，
   例如穀倉的長寬高、農舍是哪一種），再照清單蓋出來。畫面和現在一模一樣，測試全過，這一步只是拆開。
2. **烘焙工具** `tools/bake_level.gd`：跑一次自動擺設，把清單存成 `levels/ranch.tscn`——每個物件一個節點，
   節點上直接顯示模型。之後開遊戲：**有這個檔就照它蓋，沒有才自動擺**。
3. **物件庫**：每種物件一個小場景（`levels/kit/穀倉.tscn`、`木桶.tscn`……），在編輯器裡從檔案面板拖進場景就是新增。
   穀倉大小、農舍種類這類參數在屬性面板改。
4. **編輯器裡的地形和貼地**：場景檔裡放一個地形節點，編輯器裡就畫出地形（照同一個種子算）；
   物件放下去自動貼地；房子、穀倉這類建築搬到哪，地面就在底下自動整平（整平區從建築位置推出來，不另外擺）。
5. **擺設檢查**：把現在測試裡的規則集中成一支檢查——貼地、不重疊、柵欄不穿房子、撤離區淨空、
   出生點有地方、恐龍能到的最高點低於圍牆。編輯器裡按一個按鈕跑，有問題的物件標紅、列出來；測試也跑同一支。

每一步做完遊戲都能玩、測試都過。

## 另一個做法（不建議先做）：遊戲裡的編輯模式

在沙盒按一個鍵進編輯模式，用滑鼠點選、拖動、轉向、從清單加東西，存成檔。
好處是**不用裝 Godot、邊玩邊調**；壞處是選取、移動手把、復原、多選、物件清單都要自己做，
工作量大約是上面的三到四倍，而且做出來一定比 Godot 編輯器陽春。
如果調場景的人不會用 Godot，再考慮先做這個的最小版（只能移動、旋轉、刪除、存檔）。

## 要先決定的（已決定）

1. **誰來調場景？** 會開 Godot 編輯器 → 走建議做法；不會 → 要做遊戲裡的編輯模式
2. **一張地圖還是多張？** 多張的話，場景檔一張地圖一個，大廳加一個選地圖
3. **烘完之後還要不要「重新自動擺」？** 建議不要：重新產生會蓋掉手調的結果。要大改就從 git 拿舊版，
   或重烘之後手動把要留的搬回來

## 刻意不做

- 編輯器裡即時預覽霧、光、描線：遊戲裡看就好，編輯器只管位置
- 自動擺設繼續進化（更聰明的亂數規則）：有了手調之後，自動擺只負責出初稿
