# 選裝選單（派對模式，先不收錢）

像 CS 的買裝備畫面，只在派對模式的準備階段能用。草案 3.1、5.1 的第一步：先把「選」做完，「買」以後再接。

## 使用者決定（2026-10-31）

- 選單只在派對的準備階段（party.gd 的 `prep`，15 秒）能用。準備一開始自動打開；準備中按 B 或 Esc 關、再按 B 打開；準備結束自動關，這回合不能再換（死掉等重生也不能開）。
- 沒選的人只帶左輪（按 1 沒反應）。
- 死掉不能換：重生照這回合準備階段選的帶。下一回合準備階段可以重選，選單打開時預設選中上一回合的，不選就維持上一回合的。第一回合沒選 = 只有左輪。
- 電腦牛仔：從單管散彈、槓桿步槍隨機拿一把，不給炸彈長矛。
- 不要「隨機」選項。
- 其他模式（搶蛋、死鬥、恐龍決鬥、對抗、沙盒、靶場、恐龍沙盒）沒有準備階段，維持全帶、1 鍵輪流換長槍，不受選單影響。只有派對模式用選裝。

## 版面

```
┌──────── 選裝（剩 12 秒）────────┐
│ 主武器（1 鍵）                   │
│  [1] 單管散彈   免費             │
│  [2] 槓桿步槍   免費  ◀ 已選     │
│  [3] 炸彈長矛   免費             │
│  [0] 不帶（只用左輪）             │
│ 副武器（2 鍵）  左輪              │
│ 裝備  補血包 ×3（3 鍵）  炸藥（4 鍵）│
│                  B／Esc 關閉     │
└─────────────────────────────────┘
```

畫面左邊偏中，不蓋準心。主武器清單從表格的欄位產生（左輪不列），名字是表格的 `display_name`。

## 資料放哪

- `cowboy/weapons/weapons.csv` 多一列 `price`（價格），四把都是 0。`weapon.gd` 讀表時把它套到 `Weapon.price`。
- 玩家選的是 `cowboy/viewmodel.gd` 的 `static var pick`（weapon_scenes 的索引，-1 = 只有左輪）。static 所以牛仔死了重生（新節點）還在。
- 派對模式的限制在 `viewmodel.gd` 的 `_main_pick()`（1 鍵）和 `_wheel_target()`（滾輪），到用的時候才問是不是派對模式，不在 `_ready` 判斷。
- 電腦牛仔的槍由主機在 `party.gd` 的 `_spawn_cowboy` 決定，生出來就切到那把。它不用 `pick`，因為 `pick` 是本機玩家的。
- 選單是 `buy_menu.gd`，由 main.gd 建在 `$UI/Root` 底下（party_hud 之後），數字鍵先給它。開著時游標不鎖。

## 沒做的

- 收錢：價格現在全 0，還沒有扣錢、也沒有主機檢查。
- 副武器和裝備可選：現在固定左輪、補血包 3 包、炸藥。
- 隨機：不做。

## 以後接草案 5.1 B（購買）的做法

1. 加錢：玩家有錢包（先定數字，數值進 balance.csv）。
2. 客戶端按購買 → `request_kit` 送給主機（`@rpc any_peer`，同 `request_respawn_at`）。
3. 主機檢查：是本人、現在是準備階段、編號合法（0 或表裡有的主武器）、錢夠。通過才扣錢、記下這回合的選擇。
4. 斷線重連：錢和選擇跟著編號搬（party.gd 的 `rekey` 已經是這個做法）。

ponytail: 主機現在不檢查玩家開槍用的是不是選的那把（傷害請求沒帶槍的編號）。有人作弊再補。
