# OvD 玩家操作設定：研究與規劃

2026-10-18｜子代理研究、使用者同意第一版範圍；**選單要一次做**（設定視窗的所有分頁一起做，不要一項一項上）。行號以當天 main 為準。

**做法定案（2026-10-18）**：第一版 7 項照第 4 節做，在 `settings.gd`。舉槍倍率使用者選「維持現在手感」：倍率 1＝跟腰射一樣，不自動按視野減速（第 2 項備註的做法不採用）。大廳同時改成兩層主選單：首頁「連線對戰／單人練習／設定／離開遊戲」，時段搬進設定的「畫面」頁。

## 0. 先講結論

- **最該先修的不是加選項，而是一個現有的坑**：專案的畫面縮放設成 `canvas_items`（project.godot 第 23 行），而 `fighter.gd` 的 `mouse_look` 回傳的是 `e.relative`。Godot 文件寫明：`relative` 會跟著畫面縮放倍率縮放，**滑鼠靈敏度會隨視窗大小變**（全螢幕和視窗模式手感不同、Retina 螢幕也會不同）。要改成 `e.screen_relative`。這一行要跟靈敏度設定一起做，不然玩家調好的數字換個視窗大小就不準了。
- 第一版建議做 7 項：滑鼠靈敏度、舉槍靈敏度倍率、上下反轉、視野（FOV）、手把靈敏度、主音量、鏡頭晃動強度，外加「大廳也能開設定」。大約 1.5～2.5 天。
- 蹲下已經有「C 切換／Ctrl 按住」兩個鍵，瞄準也已經有按住／切換，**這兩個不用再做開關**。
- 按鍵重新綁定、分類音量、手把死區和反應曲線放第二版。
- 不能被設定破壞的設計：沒有準心、舉槍會晃、閉氣吃體力、後座力是真的轉視角。這些都走 `rotate_view`，**靈敏度只能乘在滑鼠和搖桿的輸入上，不能乘在 `rotate_view` 裡面**（後面細講）。

### 2-2 靈敏度單位和跨遊戲換算

- 每款遊戲的「靈敏度 1.0」代表的角度不同。CS2 和 Apex 是 0.022°／點，Valorant 是 0.07°／點（換算網站一致，可信）。所以 Valorant 1.0 ≈ CS2 3.18。
- 玩家心裡的共同單位是**「幾公分轉一圈」（cm/360）**：轉一圈的公分 = 360 ÷（每點角度 × DPI）× 2.54。
- **換遊戲時 FOV 不影響轉一圈要幾公分**，只影響畫面看起來移動多快。
- 舉槍靈敏度的「對齊」有好幾種流派（以畫面中心換算、以畫面邊緣換算等），網站稱為 monitor distance。最簡單、也最常見的預設是「**用視野的 tan 比例縮**」：舉槍靈敏度 = 腰射靈敏度 × tan(舉槍 FOV／2) ÷ tan(腰射 FOV／2)。這樣舉槍後畫面中心附近的東西，滑鼠動一樣的距離，在螢幕上移一樣多。

建議 OvD 顯示一個「靈敏度 1.00」，1.00 就是現在的手感，**不要直接顯示弧度**。介面可以另外小字顯示「約 X 公分轉一圈（800 DPI）」，給想對齊其他遊戲的人參考。

### 2-3 FOV 的水平和垂直

- 同一個畫面，可以用垂直角度描述，也可以用水平角度描述。16:9 螢幕：**垂直 70° ＝ 水平約 102°**；垂直 43° ＝ 水平約 70°。
- 換算：水平 = 2 × atan(tan(垂直／2) × 寬高比)。
- Godot 的 `Camera3D.fov` **預設是垂直角**（`keep_aspect` 預設 `KEEP_HEIGHT`）。`cowboy.gd:396` 的散布線計算也已經照垂直角寫。
- Hunt 的 85–110 若是水平角，換成垂直約 53–74（16:9），OvD 現在的 70 垂直落在這範圍偏高的位置。**Hunt 是哪一種不確定**，所以不要拿數字直接對。
- 建議介面**顯示水平角（16:9 換算）**，因為多數 PC 玩家講的「FOV 100」是水平的；程式內部存垂直角。

## 3. Godot 4 實作要點

### 3-1 滑鼠靈敏度

- 用 `InputEventMouseMotion.screen_relative`，不要用 `relative`。官方文件：`relative` 會乘上 content scale factor（由 stretch 設定決定），**滑鼠鎖定模式下靈敏度會隨解析度不同**；`screen_relative` 不縮放。OvD 用 `canvas_items` 加基準 1600×900，視窗放大到 3200×1800 時 `relative` 會只剩一半。
- 改成 `screen_relative` 之後，現有手感會變（看玩家平常的視窗大小，可能變快一倍）。**基準值要重調**：在 1600×900 視窗下兩者相同，所以 0.0025 保持不動，只是大視窗的玩家會覺得變快，叫他們調低就好。
- 只改 `fighter.gd` 的 `mouse_look` 一個地方，牛仔和恐龍一起受益。設定的倍率也建議乘在這裡（或乘在兩個角色各自的常數上），**不要乘在 `rotate_view`**：`rotate_view` 同時被舉槍晃動（`_update_breath`）、後座力用，乘在裡面會讓靈敏度高的人後座力和晃動也變大。
- 舉槍減速：在 `cowboy.gd:409` 乘上 `tan(_camera.fov/2) / tan(hip_fov/2) × 舉槍倍率`。用「當下的 fov」算，舉槍過渡中會平滑地變慢，不會一下跳。手把那條（425 行）也要乘同一個係數。
- `Input.use_accumulated_input` 預設開，一幀只來一個合併過的事件，FPS 用這樣就好。
- 原始輸入、滑鼠加速：Godot 在 Windows 鎖定滑鼠時是否用原始輸入、macOS 有沒有系統加速，**不確定**，第一版不做開關，列為測試項目（兩台機器各轉一圈量公分）。

### 3-2 FOV

- 改 `Camera3D.fov`（垂直角）。OvD 是 `viewmodel.gd:316` 每幀用 `lerpf(hip_fov, ads_fov, ads)` 覆蓋，所以**改 `hip_fov` 就好**，不要直接改相機。
- **坑：槍跟世界用同一台相機畫**。FOV 變大，槍在畫面上會變小、往畫面中間縮，`hip_fov` 的註解也說擺位是照 70 調的。
  - 舉槍（ADS）時準星對齊畫面中心這件事不受 FOV 影響（準星在光軸上），所以 `ads_fov` **建議固定 43 不跟著設定動**，舉槍放大倍率也一致、對大家公平。
  - 腰射時槍會變小一點。第一版先接受，範圍收窄（見第 4 節）。真要「槍不跟著 FOV 變」得另開一台只畫槍的相機（SubViewport 疊上去）或在槍的材質裡用固定投影，這是第二版以後的事。
- 散布線（`cowboy.gd:396`）已經用 `_camera.fov` 動態算，FOV 改了自動正確。
- 連線公平：FOV 越大看得越廣，上限不要給太高。

### 3-3 按鍵重新綁定

- 執行時改：`InputMap.action_erase_events(動作)` 後 `InputMap.action_add_event(動作, 事件)`；只想換鍵盤那顆、保留手把那顆，就用 `action_get_events` 找出鍵盤事件，`action_erase_event` 刪單一個。
- 等玩家按鍵：一個「請按下新按鍵」的小視窗，在 `_input` 收到 `InputEventKey`／`InputEventMouseButton`／`InputEventJoypadButton` 時記下來，Esc 取消。
- 存檔格式：**不要把 InputEvent 物件直接塞 ConfigFile**（雖然可以，但讀回來是反序列化物件，官方文件有警告來源不可信時的風險，玩家也看不懂）。存成簡單的值：
  ```
  [keys]
  fire = ["mouse", 1]
  sprint = ["key", 4194325]      # physical_keycode
  ```
  專案的 [input] 已經用 `physical_keycode`（不同鍵盤排列位置一樣），重綁也照用。
- 衝突：同一個鍵綁兩個動作時要提示。注意 OvD 本來就有**刻意共用**：`sprint` 同時是閉氣（舉槍時）；這是同一個動作，不算衝突。
- `main.gd:277` 的操作說明表 `CONTROLS` 是手寫的，註解寫「改了按鍵要回來改這張表」。做重綁時這張表要改成從 InputMap 讀，不然會顯示錯的鍵。
- 要有「恢復預設」：開遊戲時先記下 `ProjectSettings` 的原始事件（`InputMap.load_from_project_settings()` 可整個重載）。

### 3-4 設定存檔

- 繼續用 `user://settings.cfg` 和 `ConfigFile`，分節：`[controls]`、`[display]`、`[audio]`、`[keys]`。現有 `_save_setting` 每改一次讀寫一次檔，拉桿拖動時會連續觸發很多次；拉桿用 `drag_ended` 或放開後再存即可，不必改寫存檔函式。
- 讀不到的值一律回預設（`get_value` 第三個參數），舊玩家的設定檔不會壞。

### 3-5 連線遊戲

- 所有這些設定都只動本機：靈敏度、FOV、晃動、音量、按鍵都不會同步給別人，也不該同步。
- 視角朝向本來就是由本機算好再同步（MultiplayerSynchronizer），伺服器不在乎你用多少靈敏度。
- 專用伺服器（無畫面）也會跑 `_load_settings`，現在會碰 UI 節點；新加的設定程式要確保無頭模式下不出錯（音量、畫面相關呼叫在無頭時是空操作，一般沒事，但要測一次 `--headless`）。
- 散布、子彈角度都以「度」計算，跟 FOV 無關，不會因為改 FOV 而影響命中判定。

### 以後

- 各武器／各鏡分開的舉槍靈敏度（像 Hunt）：等有倍鏡、等不同武器的舉槍 FOV 不同時再做。
- 槍不跟 FOV 變（另一台相機畫槍）：FOV 範圍要放寬時才需要。
- 準星選項（Hunt 2024 改成預設開置中準星）：跟「刻意沒準心」的設計衝突，要先討論，不是技術問題。
- 色盲模式：OvD 目前靠顏色傳的資訊不多（血條、命中紅色），等 HUD 定型再看。
- 手把加速（推到底一段時間後變快）、水平垂直速度分開。
- 滑鼠加速、原始輸入開關：先量測確認 Godot 有沒有問題，沒問題就永遠不做。
- 音樂音量：目前沒有音樂。語音聊天音量：沒有語音聊天。

## 5. 設定畫面怎麼排

一個獨立的設定視窗（`Window` 或全螢幕 `Panel`），用 `TabContainer` 分頁。Esc 選單放「設定」按鈕，大廳也放一顆，開同一個視窗。

| 分頁 | 第一版內容 | 第二版加 |
|---|---|---|
| 操作 | 滑鼠靈敏度、舉槍靈敏度倍率、上下反轉、瞄準按住／切換、手把靈敏度 | 手把死區、曲線、跑步切換 |
| 按鍵 | （第一版沒有，可先放現在的操作說明表） | 重新綁定、恢復預設 |
| 畫面 | 視野、鏡頭晃動強度、垂直同步、幀率上限、像素風、時段（目前在大廳下拉，可兩邊都放） | 走路晃槍、散布線、命中提示 |
| 聲音 | 主音量 | 分類音量 |

小原則：
- 拉桿旁邊顯示數字，可以直接打數字（靈敏度玩家很在意小數點）。
- 改了馬上生效，不用按「套用」；遊戲中開設定時也能邊調邊看（Esc 選單現在會暫停操控，FOV、晃動要回遊戲才看得到效果，可接受）。
- 每頁一顆「恢復預設」。
- 視窗開著時 Esc 只關視窗（跟現在 ControlsDialog 的做法一樣，`main.gd:253`）。

## 6. 第一版工作量和風險

**粗估 1.5～2.5 個工作天**：

| 工作 | 估計 |
|---|---|
| `screen_relative` 修改＋兩種視窗大小實測 | 0.25 天 |
| 設定視窗（分頁、拉桿元件、大廳和 Esc 都能開、搬現有三個選項） | 0.75–1 天 |
| 靈敏度、舉槍倍率、反轉、手把靈敏度接進 cowboy／dino | 0.25 天 |
| FOV＋兩端截圖檢查槍擺位 | 0.25–0.5 天 |
| 主音量、鏡頭晃動強度 | 0.25 天 |
| 測試（test_battle.gd 加幾個檢查、無頭伺服器跑一次） | 0.25 天 |

**風險**：

1. **舉槍減速會改變大家熟悉的手感**。現在舉槍沒減速，加上後舉槍變慢約 44%。要不要用這個當預設，需要試玩決定（備案：預設倍率 1.78＝手感不變）。
2. **改 `screen_relative` 也會改變手感**：用大視窗、全螢幕或 Retina 的人會覺得變快。發版時要在說明寫一句「靈敏度算法修正，覺得變快請在設定調低」。
3. **FOV 和槍擺位**：範圍放太寬，槍會變太小或被切到。第一版收窄到水平 90–110，用截圖工具確認兩端。
4. **不能把設定乘錯地方**：靈敏度乘在 `rotate_view` 裡會讓後座力、舉槍晃動跟著變大；鏡頭晃動強度不能動到 `_update_breath`。要在 `test_battle.gd` 加一個檢查：靈敏度設 2 倍時，同一發後座力造成的視角變化不變（已有 `vm1._kicks` 那段可參考）。
5. **macOS 的滑鼠加速**：不確定 Godot 鎖定滑鼠時拿到的是不是原始位移，Mac 和 Windows 手感可能不同。第一版不處理，先量。
6. **設定檔相容**：只新增鍵，不改舊鍵，舊玩家的檔不會壞。
