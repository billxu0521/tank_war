# 物理規則：材質 × 攻擊的查表

日期：2026-11-10。接在 [玩具積木場景（二）](2026-11-08-玩具積木場景-二.md) 後面，對照 [規則草案 10-28](../企劃/規則草案-2026-10-28.md) 第 4 節和 [子彈種類與穿牆](2026-10-15-子彈種類與穿牆.md)。

## 使用者原話
「需要定義什麼狀態下子彈可以穿牆、可以破壞物件；另外也可能需要火焰、爆炸、風吹等效果。想建構一個比較正式的物理規格世界。」

## 目標、不做什麼
- 目標：場上每個物件有一個「材質」，每次攻擊有「種類＋力道」，查一張表就知道結果（壞／穿／燒／推／無效）。數字都在 `balance.csv`，企劃改表不改程式。
- 不做真的物理模擬（受力、應力、倒塌）：伺服器算不動、各台算出來不一樣、手感調不出來。碎塊飛行照舊各台自己模擬、停下來以主機為準。

## 材質表

| 材質 | 鍵 | 耐久 | 可燃 | 厚度 | 碎塊可推 | 場上誰用 |
|---|---|---|---|---|---|---|
| 木頭 | `wood` | 1 | 是 | 1 | 是 | 牆、屋頂、門窗、柵欄、樹冠、派對方塊房子等級 1 的塊 |
| 樹 | `tree` | 2 | 是 | 2 | 是 | 樹幹、仙人掌 |
| 磚 | `brick` | 2 | 否 | 2 | 否 | 柱子、二樓以上樓板、斜坡、掩體方塊 |
| 鐵 | `iron` | 3 | 否 | 3 | 否 | 還沒有（之後的鐵皮屋；靶場的金屬板） |
| 石頭 | `stone` | 3 | 否 | 99 | 否 | 地基、一樓地板、石頭、安全屋 |

- 耐久 = 現在的「等級」（1、2 挨幾下倒，3 打不壞），所以現有的塊、測試、草案 4.2 都不用動：材質只是在等級上多掛「可燃、厚度、可推」。
- 沒給材質的塊照等級給預設（1 木頭、2 磚、3 石頭），`arena_map.gd` 的樹、石頭才明寫材質；灰盒的房子不用改切法。
- 耐久 3 的材質任何攻擊都無效（草案 4.2：「不以打三次拆掉」）。鐵和石頭差在厚度：重型子彈穿得過鐵皮、穿不過石頭。穿不等於壞。
- 沒有材質的東西（地形、人、舊牧場的房子）照舊：擋子彈、不壞、不燒。
- 碎塊承襲它那塊的材質（現在碎塊進 `plank/double_plank/metal` 群組，改成材質鍵當群組名）。

## 攻擊種類表

| 種類 | 鍵 | 力道 | 範圍 | 誰發出 | 現在的程式 |
|---|---|---|---|---|---|
| 子彈 | `bullet` | 穿透力：炸彈長矛 0、左輪 1、散彈 1、步槍 2（重型彈 3 之後再開） | 一條線 | 獵人 | `cowboy/bullet.gd`（`power`） |
| 衝撞 | `charge` | 跑步 2（速度 ≥ `dino_run × toy_charge_ratio`）、走路 0 | 身前長方體 | 尼諾拉 | `boss.gd _smash_ahead` |
| 甩尾 | `sweep` | 2 | 後方半圓（半徑 `sweep_radius`） | 尼諾拉 | `boss.gd _wreck_around` |
| 爆炸 | `blast` | 炸藥 1、炸彈長矛 0（照現況，長矛的爆炸不拆）、高級炸彈 2（草案 5.3，之後） | 球，半徑 6（炸藥）、2（長矛） | 獵人 | `cowboy/viewmodel.gd _explode` → `ToyBuild.blast` |
| 火 | `fire` | 火球直接命中 2；燒（第二版）看可燃不看力道 | 火球：命中點一次；油火：區域、持續、會擴散 | 尼諾拉火球、獵人打破油燈 | `fireball.gd`、`oil_fire.gd` |
| 風 | `wind` | 推力（公尺／秒²），不是力道 | 全場一個方向 | 場景（第三版） | 只有 `Fx.WIND` 畫煙用 |

- 力道是整數 1～3，跟耐久同一把尺，查表只比大小。
- 衝撞走路力道 0 是因為走路撞不拆（`toy_charge_ratio`），只推開碎塊（`toy_nudge`）。

## 對照表：攻擊 × 材質

| | 木頭（1，可燃，厚 1） | 樹（2，可燃，厚 2） | 磚（2，厚 2） | 鐵（3，厚 3） | 石頭（3，厚 99） |
|---|---|---|---|---|---|
| 子彈 力道 1（左輪、散彈） | 穿，剩 0 | 擋 | 擋 | 擋 | 擋 |
| 子彈 力道 2（步槍） | 穿，剩 1（還能再穿一片木頭） | 穿，剩 0 | 穿，剩 0 | 擋 | 擋 |
| 子彈 力道 3（重型彈，之後） | 穿，剩 2 | 穿，剩 1 | 穿，剩 1 | 穿，剩 0 | 擋 |
| 衝撞 跑步（2）、甩尾（2）、火球命中（2） | 壞（一下） | 壞（兩下） | 壞（兩下） | 無效 | 無效 |
| 衝撞 走路（0） | 無效 | 無效 | 無效 | 無效 | 無效 |
| 爆炸 炸藥（1） | 壞（一下） | 無效 | 無效 | 無效 | 無效 |
| 爆炸 高級炸彈（2，之後） | 壞 | 壞 | 壞 | 無效 | 無效 |
| 火 燒（第二版） | 燒 → 燒掉 | 燒 → 燒掉 | 無效 | 無效 | 無效 |
| 風（第三版） | 推碎塊 | 推碎塊 | 無效 | 無效 | 無效 |

壞、穿、燒、推只有四條規則，整張表都是它們算出來的：

- **壞**：力道 ≥ 耐久 才扣 1 點，扣到 0 鬆脫；耐久 3 永遠無效。全速衝撞每下扣 `toy_plow_dmg`（現在 1）。這就是現在 `smash(max_level)` 的判法，一行都不用改。
- **穿**（只有子彈）：力道 ≥ 厚度 才穿；穿過後力道減掉厚度，再往下一片比；減到 0 下一片就擋。所以步槍穿兩片木牆或一片磚，左輪只穿一片木牆。原因：一發子彈穿整棟房子沒人躲得掉。
- **穿過傷害打折**：每穿一片傷害乘 `hit_pierce_dmg`（0.6）。原因：10-15 版「穿過不減傷」是第一版偷懶，隔牆打人要比正面弱。
- **子彈不壞積木**：穿過的塊不扣耐久。原因：步槍 16 發就能拆一面牆，比尼諾拉還會拆；草案沒給子彈建築傷害。
- **燒**（第二版）：可燃的塊在火的範圍裡累積 `fire_catch_seconds` 就燒掉（鬆脫、不留碎塊），原地生一灘新火。不可燃的擋火不傳。
- **推**（第三版）：只推飛行中的碎塊，材質可推且質量 < `wind_max_mass`；停下來的不推。原因：停下來的碎塊是導航網格的一部分，推一下就要重烘。
- 碎塊挨打：碎塊是靜態物，子彈照它的材質穿、不壞；衝撞踢（`toy_kick`）照舊不看材質。

## 範圍效果

### 爆炸（球形、一次）
- 人：照現在，`Explosive.damage` 中心滿傷、邊緣 0，中間有場景擋住就炸不到。
- 積木：半徑內中心距離 < 半徑的塊，力道查表，不看遮擋（ponytail：方塊房子牆互相擋住，爆炸會穿過去拆後面的木頭塊，照舊）。
- 碎塊（第二版）：半徑內飛行中或停著的碎塊，可推的給一個從爆心往外的衝量（`blast_push`，公尺／秒），停著的先換成 `RigidBody3D`（走現在 `_kick` 的路）。原因：炸藥炸在碎塊堆裡碎塊不動很假。
- 油燈：照現在，範圍內的燈一起破（各台各自）。

### 火（區域、持續、會擴散）
- 火源：油燈破（`oil_fire.gd`，半徑 2.2、燒 12 秒，照舊）；火球打到可燃的塊（第二版新增）在命中點留一灘小火（`fire_ball_radius`、`fire_ball_seconds`）。
- 燒人：照現在，站在火裡每 `TICK` 扣血。
- 燒積木（第二版）：主機每 `fire_tick` 秒看每灘火 `covers()` 裡站著的可燃塊，累積著火秒數（`_burning[i]`），滿 `fire_catch_seconds` 就 `_break`（不生碎塊，燒成灰）並在那塊中心生一灘新火（`fire_spread_radius`、`fire_spread_seconds`）。
- 上限：全場同時最多 `fire_max` 灘（超過不生新的）、同一棟每 tick 最多燒 `fire_per_tick` 塊。原因：一棟 1600 塊的大樓一把火就是 1600 次 `_break`，要壓住伺服器和連線量。
- 擴散方向：第三版加風以後，逆風的塊著火秒數 ×2、順風 ×0.5。
- 不燒碎塊、不燒人以外的東西（恐龍照 `ignite`）。

### 風（一個方向的推力，第三版）
- 全場一個方向＋強度（`wind_x`、`wind_z`、`wind_speed`）寫在表裡，每台一樣，不用同步。`Fx.WIND` 改成讀表，煙、火星、火苗的斜法跟著走。
- 推碎塊：飛行中的 `RigidBody3D` 每物理幀加 `wind_speed × 可推` 的加速度；各台各自加，最後位置照主機 `_settle`，所以中途可能不一樣、停下來一樣（跟現在的飛行同一個約定）。
- 推火：火苗畫面斜（已有）、擴散偏順風（上面）。
- 不推人、不推子彈、不推火球：風會把手感搞壞，而且草案沒提。

## 連線：誰算、送什麼

| 效果 | 誰算 | 送什麼 | 現在有沒有 |
|---|---|---|---|
| 壞（鬆脫） | 主機 | `_break(ids, gone, from, power, dir)` | 有 |
| 子彈穿牆 | 開槍那台（子彈只在開槍那台算傷害） | 傷害請求照舊走主機 `deal_damage`；穿牆本身不送，別人畫面上的子彈用同一張表自己算（`Balance.digest()` 版本檢查保證表一樣） | 有（分級關著） |
| 爆炸 | 主機算傷害、拆積木 | `_explode(at, kind)` 各台播，拆走 `_break` | 有 |
| 火 燒人 | 主機 | `take_damage` | 有 |
| 火 燒積木、擴散 | 主機 | 燒掉走 `_break`；新火送 `_fire_at(pos, radius, seconds)`（各台用位置當種子生一樣的火） | 第二版新增 |
| 爆炸推碎塊 | 主機 | 照 `_kick(key, impulse)` | 第二版 |
| 風 | 各台（表裡的常數） | 不送；停下來照 `_settle` | 第三版 |

- 主機決定結果、其他台只播畫面，是現在積木的約定（toy_build.gd 開頭），這份規格不改它。
- 子彈是例外：子彈在開槍那台飛，主機只檢查傷害額度。穿牆的判斷靠「每台同一張表」而不是主機下令。原因：子彈一幀飛三四公尺，等主機回覆太慢。

## 程式架構：最少的改動

- 新檔 `hit_rules.gd`、`class_name HitRules`，只有 static 函式，讀 `Balance`：
  - `MATS := [&"wood", &"tree", &"brick", &"iron", &"stone"]`
  - `level(mat) -> int`（耐久）、`burns(mat) -> bool`、`thick(mat) -> int`、`pushable(mat) -> bool`
  - `default_mat(level) -> StringName`（1 木頭、2 磚、3 石頭）
  - `breaks(force, mat) -> bool`：`level(mat) < 3 and force >= level(mat)`
  - `pierce(force, mat) -> int`：穿過後剩的力道，-1 = 擋
- 這是整份規格唯一查表的地方；衝撞、甩尾、爆炸、火球的力道從表讀（`hit_charge_force`、`hit_sweep_force`、`hit_blast_force`、`hit_fireball_force`），不寫死 2、2、1、2。

| 檔案 | 改什麼 |
|---|---|
| `balance.csv` | 加材質列 `mat_<鍵>_hp / _burn / _thick / _push`（5 × 4 = 20 列）、力道列 4 列、`hit_pierce_dmg`。第二、三版再加火和風的列 |
| `cowboy/weapons/weapons.csv` | 加 `pierce` 列：左輪 1、散彈 1、步槍 2、長矛 0 |
| `hit_rules.gd` | 新檔（上面） |
| `toy_build.gd` | 每塊多一個 `_mat`（`make` 的 brick 第 6 格，沒給照等級）；`ARMOR_GROUP` 刪掉、碎塊群組改材質鍵；`armor_of(shape)` 改名 `material_of(shape)` 回材質鍵。`smash` 不動（`max_level` 就是力道） |
| `cowboy/bullet.gd` | `ARMOR` 字典刪掉；`pierces` 改問 `HitRules.pierce`，拿掉 `AMMO_TIERS` 那行早退；穿一片就 `power -= thick`、`_pierced += 1`；`_impact` 的傷害乘 `hit_pierce_dmg ^ _pierced` |
| `cowboy/weapon.gd` | `@export var pierce := 1`，`apply_table` 讀進來；`AMMO_TIERS` 保持 false（B 換彈還關） |
| `cowboy/viewmodel.gd` | `b.power = w.pierce`（第 608 行，原本 `ammo + 1`） |
| `boss.gd`、`fireball.gd`、`toy_build.gd blast` | 力道改讀 `HitRules` 的表值（三處各一行） |
| `arena_map.gd` | `_tree` 的樹幹、仙人掌給 `tree`，石頭給 `stone` |
| `main.gd` | 靶場 `PIERCE_WALLS` 的群組改 `wood / brick / iron` |
| `tests/combat.gd`、`tests/match.gd` | 群組名、`armor_of`、「子彈不穿牆（分級先關）」案例改掉（下面） |

- 不加 autoload：static 類別就夠，跟 `Balance`、`Explosive` 同一種寫法。
- 不改 `smash` 的簽名：四個呼叫的地方和十幾個測試都不用動。

## 分版

### 第一版：材質表＋子彈穿牆
- 做：`hit_rules.gd`、表的列、每塊有材質、子彈按槍穿牆＋打折、衝撞／甩尾／爆炸／火球的力道改讀表。
- 不做：燒積木、風、重型彈、高級炸彈、鐵進地圖。
- 玩起來的差別：步槍穿木牆（打折）、左輪穿一片木牆、都穿不過柱子和石頭；其他跟現在一樣。
- 測：`godot --headless --path . --script test_battle.gd`。看最後一行 `OK：…`，整段沒有 `FAIL`、`SCRIPT ERROR`、`Parse Error`（有 parse error 也會回 0，不能只看 exit code）。
  - `tests/match.gd _toy_bullet_case`：力道 2 的子彈穿木頭、停在磚前；力道 1 的停在第二片木頭前；穿過後傷害 × 0.6。
  - `tests/match.gd _toy_b_armor` → `material_of`：等級 2 沒給材質回 `brick`、樹幹回 `tree`。
  - 新案例 `_rules_table`：`HitRules.MATS` 每個鍵的 4 列都在表裡（`Balance.missing` 空）；`breaks(2, stone) == false`、`pierce(2, wood) == 1`、`pierce(1, brick) == -1`。
  - `tests/combat.gd` 靶場三面牆的案例換群組名後照過。
  - 連線：`tools/net_check.sh` 過（表的雜湊兩邊一樣）。

### 第二版：火燒積木、爆炸推碎塊
- 做：`oil_fire.gd` 每 `fire_tick` 燒可燃塊、`_break` 不生碎塊的參數、`_fire_at` RPC、火球落點留火、`fire_max` 上限、爆炸推碎塊。
- 測：同一個指令。新案例：一灘火旁邊一塊木頭 `fire_catch_seconds` 後鬆脫且旁邊生了新火；磚不燒；`fire_max` 灘以後不再生；火球打木牆留一灘火、打石頭不留。
- 要量：一棟 700 塊的木房子從點火到燒完幾秒、主機一幀多少毫秒（目標 < 8）。

### 第三版：風
- 做：`wind_*` 列、`Fx.WIND` 讀表、飛行中碎塊加風、火擴散順風快逆風慢。
- 測：飛行中的木頭碎塊順風落點比無風遠；停著的碎塊不動；磚碎塊不動。

### 之後（不排）
- 重型彈（力道 3）：把 `AMMO_TIERS` 打開、`b.power = pierce + ammo`，表不用改。
- 高級炸彈（力道 2）：`BLASTS` 多一種、力道讀表。
- 鐵皮屋：greybox 多一種材質就好。

## 要問使用者／企劃的
1. 子彈力道按槍（步槍 2、左輪和散彈 1）還是重開三種彈分級（B 換彈）？第一版建議按槍，之後分級疊上去。
2. 火燒掉的塊要留碎塊（燒焦的障礙物）還是燒成灰不留？建議不留，不然碎塊還要再燒一層。
3. 火燒積木、會擴散，跟草案「火球每次命中扣 1 HP」不一樣：企劃要嗎？要的話木頭幾秒燒掉（建議 3）、全場最多幾灘（建議 12）？
4. 鐵：重型子彈穿得過、什麼都打不壞，跟草案「等級 3 不可破壞」這樣對齊可以嗎？要不要在地圖放鐵皮屋？
5. 風：全場常駐一個方向，還是當事件（例如尼諾拉吼一聲吹一陣）？第三版才做，先問方向。
