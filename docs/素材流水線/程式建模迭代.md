# 程式建模迭代：用參考圖把模型逼近到「並排分不出來」

> 每一輪的截圖（`docs/image/*_iter/`）太大沒進 git，只在做的那台電腦上；定案的對照圖在 `docs/image/final/`。

2026-09-29 用這套流程做了闊葉樹（`blender/tree.py`），24 輪後放進遊戲。這份記錄流程本身和踩過的坑，
下一個物件（風車、牧場大門、木箱……）照同樣做法。

## 流程

1. **參考圖**：一張圖裡放正、右、背、左四面＋大中小三種尺寸＋細節特寫（`docs/image/tree.png`）。
   特寫很重要，表面質感要靠它定目標。
2. **建模腳本**：純 Python，背景跑 Blender，不開視窗、不走 MCP：
   `Blender --background --factory-startup --python blender/tree.py -- --out models/trees.glb --preview v.png`
   一次跑完：建模 → 匯出 glb → 照參考圖的排法渲染預覽。
3. **一輪迭代**：`tools/model_iter.sh tree <版號>` → `docs/image/tree_iter/v<N>.png` 和 `v<N>_對照.png`（上參考、下我們）。
   Cycles 一輪約 85 秒。
   送審前先過自動檢查（`blender/pipeline.py`：面數預算、沒長出來的零件、葉片卡貼圖座標、反面），沒過 model_iter.sh 直接停，
   不佔用審查輪數（仙人掌的刺兩版沒生成、闊葉樹葉子整片消失，都是這種）。
4. **審查**：子代理看對照圖，第一行只給「通過／不通過」，不通過列最多 6 點「可以直接改成參數」的修改。
   同一個子代理一路延續（它記得前幾輪說過什麼）。
5. **使用者最後決定**：子代理通過之後，使用者看對照圖還可以否決（這次否決了兩次）。

## 最重要的幾個教訓

**預覽的渲染方式要跟參考圖一樣。** 前 9 輪用 EEVEE，葉團之間沒有暗縫，怎麼擺都糊成一團，審查一直在錯的方向打轉。
第 10 輪改 Cycles（光線追蹤，參考圖就是這種），葉團一顆顆分開、之後才開始收斂。這是整個過程最大的轉折。

**審查標準要嚴。** 第 3 輪子代理就判「通過」，使用者看了否決。之後把標準寫成「並排分不出是不同人做的才算通過，
不要因為比上一版好就放行」，才一路修到位。

**審查者的建議會來回。** 葉團表面：第 4 輪說低頻形變像馬鈴薯、第 5 輪說太碎、第 8 輪又要低頻雜訊。
要它「直接看特寫定一個固定目標、不要再來回」之後，它自己更正並給出明確數字（稜邊約直徑 1/5）。

**建議不一定照單全收，每改一步都看圖。** 照建議推中圈 → 樹冠太扁（v17）；照建議的暖光 → 整棵變芥末色（v22）。
自己先看對照圖，明顯的錯先修再送審，比較省輪數。沒送審的中間版也留在資料夾裡，註明是試錯。

**預覽燈光 ≠ 遊戲燈光。** 審查要分清楚「模型本身的問題（會帶進遊戲）」和「預覽燈光的問題」，只有前者算不通過。
放進遊戲後還要再看一次實際畫面（這次在遊戲裡變成黑剪影，要補亮）。

## 這棵樹學到的具體做法

- **葉團**：頻率 3 的 geodesic 球（二十面體每邊切三段，180 面），頂點只沿徑向亂推 ±9%，每團再隨機轉一個角度，平面著色。
  320 面太細碎；decimate 會生出細長的爛三角形；逐頂點 ±12% 變成雜點；低頻雜訊變馬鈴薯。
- **樹冠的擺法**：分層寫死位置（公尺），不用黃金角亂撒、也不用互推（互推會把樹冠推成塔或推扁）。
  外圈八團交錯——正對四個視角的抬高、斜角的下垂，所以樹冠底面是拱形、中間露得出枝幹；中圈推到樹冠半寬 0.75 倍，兩側才直；
  頂上一顆最大的突出來。
- **樹幹**：七稜柱，從地面到分叉點連續收細（外擴分四圈漸變，突然張開會像墊了台座），根稜外推量也要漸變到零。
- **枝幹**：Y 字分叉，主枝根部約主幹 65%、線性收到 40%，分段彎；次枝在不同高度錯開分出。枝尖要收進葉團裡，不然會穿出樹冠。
- **大中小**：各自寫尺寸（公尺），不要建好再縮——縮兩次會小到不成比例。
- **材質**：不要高光（高光會把受光面的黃沖成灰，吃掉折面）。glTF 的 Specular 0 匯進 Godot 不會生效，要在程式裡設
  `metallic_specular = 0`（`main.gd` 的 `_no_specular`）。
- **不要疊照片紋理**：照片紋理會把平面折面洗掉（2026-09-29 已經把整套貼圖素材庫拿掉，全部物件都是純色平面著色）。
  樹在黃昏逆光下不補亮會變黑剪影，在線性空間補 1.25 倍（`TREE_GAIN`）。

## 審查子代理的提示要點

- 給兩張圖的絕對路徑（或一張對照圖），說明排法。
- 「只評模型本身，燈光不同不扣分，但固有色偏差要指出」。
- 輸出格式固定：第一行判定、最多 6 點、依影響大小排序、每點要能直接轉成參數。
- 使用者否決過的話，把否決理由原話轉給它，當那一輪的重點。

## 石頭（`blender/rock.py`，21 輪）

參考圖是一張 16 顆的型錄（`docs/image/rock.png`），預覽照同樣構圖、1 像素 = 1 公分擺，上下對照可以直接量位置和寬度。

**新的教訓**

- **排在一起渲染會互相投影。** 三排石頭在場景裡上下疊著，上一排把影子投到下一排，第二排整排發暗、看起來像凹洞（v7、v8）。
  改成一排一排分開渲染再疊起來。接影子的地面（shadow catcher）一樣會擋到下一排，不能用。
- **先查清楚「看起來像凹洞」是什麼。** v1、v2 以為是 bevel 切出凹痕、把倒角整個關掉，其實大半是上一排的影子。
  懷疑網格有問題時，寫幾行檢查（開放邊、反面、零件數）或單獨渲染那一顆，不要猜。
- **凸包的限制：一定是凸的，凹處會被填平。** 要凹折（台階、底部內收、兩顆之間的溝）就在凸包之後才移頂點。
  兩個凸包疊起來也做得出凹折，但一定留一條接縫（v16~v19），最後還是回到單一凸包＋凸包後 bisect 一條摺線再壓（v21）。
- **倒角要在最後、對邊做。** 在點上加倒角帶會被大面裡的點拆成好幾段小角度，達不到門檻，等於沒做（v13）。
  凸包、清碎面都做完才 `bmesh.ops.bevel`，只選凸稜（`calc_face_angle_signed() > 0`），凹折不倒。
- **面要有主次。** 全面加點（v5、v6）面會大小平均，變成蛋。做法是十幾個點做主平面，再在最大的幾個面裡加少量點、只外推一點點。
- **形狀參數要每顆各自指定。** 審查說「頂部收 33%」是針對某幾顆，套到全部就把對的也改壞了（v9）。規格裡每顆寫自己的頂形，
  少數需要的再加個別調整（`apex`、`press_right`、`lift_right`、`step`）。
- **審查者也會給錯方向，而且會自己更正。** 例如叫支撐石「往後藏」，但預覽是正面正交，往後移擋不住（v13）；
  叫副塊「往後退」結果接縫變長（v19）。每一步都看圖驗證，發現建議不對就告訴它原因，它會改建議。
- **面數預算要說出來。** 一開始沒講，v5 衝到 1.8 萬；講了之後審查會自己建議省面的做法（例如寬度 < 100px 的小石頭不倒角）。

## 全場景風格一致化（12 輪，2026-09-29）

拿掉照片貼圖之後，全部物件改成純色平面著色，用 `tools/style_iter.sh <版號>` 從 6 個固定角度拍遊戲實際畫面
（第一人稱、農莊、石頭、山崖、恐龍、俯瞰），拼成 `docs/image/style_iter/v<N>.png` 給審查子代理和人看。
審查會「取 7×7 像素平均」量顏色，驗收項目寫成數字門檻（例如地面受光面 ≥ #B8885A、任何取樣點藍色不為 0）。

**最終色盤與光線（新物件照這套驗收：受光面、暗面各取樣一次，比對樹和石頭）**

| 項目 | 值 |
|---|---|
| 色調映射 | Filmic，exposure 1.35，對比 1.05，飽和 1.0 |
| 太陽 | 顏色 (1, 0.74, 0.5)，強度 2.4 |
| 環境光 | (0.50, 0.50, 0.56)，energy 1.2，天空貢獻 0.3 |
| 天空亮度 | background_energy_multiplier 0.75 |
| 霧 | 顏色 (0.84, 0.64, 0.50)，密度 0.001，sun_scatter 0.1 |
| 天空 | horizon (1.0, 0.50, 0.10)、漸層指數 1.4、雲在 up 0.15~0.35 淡入 |
| 地面頂點色 | DIRT (0.93, 0.76, 0.50)、GRASS (0.82, 0.65, 0.39)、WHEAT (0.70, 0.56, 0.33) |
| 樹（線性） | 葉 (0.16, 0.19, 0.04)、樹皮 (0.22, 0.12, 0.06) |
| 石頭（線性） | (0.32, 0.17, 0.08)；山崖是同色系、明度約 ×0.44 |
| 暴龍 | BODY #7E8246、BELLY #A89060、DARK #5A6034 |
| 全部材質 | 平面著色、`metallic = 0`、`metallic_specular = 0`（`main.gd` 的 `_flatten_models` 在啟動時統一設） |

**教訓**

- **色調映射決定一切。** ACES 把暗的橙褐推成豬肝紅（樹幹、石頭、煙囪全變紅）；AgX 灰悶；Filmic 最接近 Blender 預覽。
  預覽定案的物件，遊戲要用接近的管線，不然一進遊戲就走樣。
- **暖色要從光來，不要從調色來。** 加飽和度會把全場拉成單一橘褐色（藍色通道被截成 0）。
  目標的黃昏感是「受光面暖（太陽）、暗面冷（環境光）」的冷暖對比。
- **不要用增益補亮。** 樹原本在遊戲裡乘 1.25 倍，其實是在補錯的色調映射和不夠的暗面補光；管線對了就不需要。
- **固有色最後才動。** 先把光修對，量過門檻還不到才改固有色，而且只改一次（v7）。預覽定案的顏色會比預覽裡略亮略綠，因為遊戲的光比預覽暗又暖。
- **glTF 的 Specular 0 匯進 Godot 不會生效**，而且匯進來的材質預設 0.5 反光，會反射粉色的天空（牆、門廊泛粉紫）。
- **場地在峽谷裡，真正的地平線被山崖擋住**：改地平線顏色的三版都改在看不到的地方（v9~v11）。改天空之前先確認畫面上看得到的是天空哪一段。
- **審查者會量錯、也會自己更正**：像「俯瞰的亮黃光暈」先後被歸因成霧、撤離區、提燈，最後判定是正常受光。要它說清楚怎麼量、哪一段，數值兩版不動就去查原因，不要繼續調同一個旋鈕。

## 農舍三種（`blender/house.py`，9 輪，2026-09-30）

參考圖是一張零件型錄（`docs/image/house.png`），目標是左上角那棟的做工；另外兩種（圓木小屋、直板高屋）要「同一個美術做的另外兩棟」。
預覽是左前上方的正交視角，上排正面、下排轉 180 度看背面。定案對照圖 `docs/image/final/house_v9_對照.png`。

**紋理靠幾何，不靠貼圖**：一片片搭接板（下緣翹 3 公分、下面一條暗一截的細條）、一排排長木片瓦（下緣翹起＋一條暗邊，
不然純色平面著色看起來像柏油瓦的格子）、一顆顆石頭（暗色灰縫內凹，轉角一排包正面一排包側面才不會有直縫）。
每組顏色只差亮度（±6~12%）不變色相：變色相會像拼布、深淺片交錯像棋盤格。

**教訓**

- **輪廓先對，細節後調。** 第 3 版屋脊方向錯（參考圖是山牆朝前），審查第一輪就抓出來；細節做再多，輪廓不對一眼就不像。
- **顏色要在遊戲的光下定。** 審查要的飽和橙褐（#7A4F2C）在黃昏光裡會變橘，取中間值（#876C4F）並把理由告訴它，它接受了。
  屋頂要比牆暗很多（#4A3D32），這個對比是參考圖的特徵。
- **發亮的窗在遊戲裡要弱很多**：Blender 裡發光強度 3 在遊戲會亮成純白，1.2 剛好。
- **淺色的底露出來會很跳**：圓木最上一根拿掉（不然會從屋面穿出來）後，露出淺色填縫變成一條亮帶，要補壓頂木。懷疑是什麼東西時先裁圖放大看。
- **遊戲面也要驗**：房子架高 0.45，前廊碰撞頂面要跟屋內地板一樣高（差 6 公分就卡），台階碰撞是一片 26 度的斜坡。
  `tools/test_house_walk.gd` 會讓膠囊從台階外走到門口，三種都要走得上去。蓋在斜坡上的那棟要整平地面，不然台階會懸空。

## 全部模型的紋理（main.gd `GRAIN_RULES`，2026-09-30）

純色平面看起來像塑膠。在遊戲裡給材質疊一張程式雜訊（`FastNoiseLite` 做的無縫圖），物件自己的座標三面投影（不用 UV），
照材質名字套：木頭是橫向細條（直條板是直紋）、石頭和屋瓦是斑塊、乾草是細絲、恐龍是鱗片；葉子、布、金屬、槍不加。
明暗只動十幾趴（折面的明暗差還在），並且把平均變暗的量補回 `albedo_color`，整體顏色不變。
這跟之前拿掉的照片貼圖不同：照片的明暗差太大，會把平面折面洗掉。

**原則（之後新增物件照這個驗收）**：整體偏暗偏紅、對比低；天空是最亮的，最亮處在地平線；道具和房子受光面不能比地面亮；
遠處往灰紫淡化；影子偏暖紫。

**教訓**

- **峽谷牆原本擋掉了低角度的太陽。** 拿掉之後全場直接照到，整片過亮——光要整套重調，不是只補遠景。
- **遠山吃霧會被洗成一片淡粉，看起來像方塊房子；吃燈光又會被橘色太陽照成豬肝紅。** 改成不吃燈光、明暗和淡化直接算在顏色裡，才控制得住。
- **審查者給的太陽顏色 (1, 0.62, 0.38) 會讓整張變成一片飽和橘、綠色被吃光**（跟之前「暖色要從光來、但不能拉飽和」同一個坑）。
  改用偏黃的太陽、直接把地面固有色往下調，並把理由告訴它，它接受了。
- **先取樣再猜。** 以為是麥子的其實是草地著色器畫的草；以為沒變暗的石頭其實是正對太陽。用 `magick -crop 9x9 -resize 1x1!` 取樣對照參考圖的數字最快。

## 場景小物件（`blender/kit.py`，6 輪，2026-09-30）

參考圖 house.png 裡房子以外的十樣（吊燈、木桶、木箱、方草捆、車輪、柵欄、圍欄門、繫柱架、風車、倉庫），定案圖 `docs/image/final/kit_v6_對照.png`。
借用 house.py 的材質和工具，顏色跟農舍同一套。預覽裡小東西放大顯示，匯出是實際大小。

- **改了物件位置要注意**：在 Blender 裡改 `location` 之後馬上合併，矩陣還沒更新，零件會被墊高（木桶 v1 變成漏斗）。直接在原點建、推頂點。
- **不封閉的網格自動翻面會翻錯**：木桶的蓋子被翻到背面，看起來是一片灰。蓋子、桶底的面要自己確認朝向。
- **草捆要靠很多細條才讀得出是草**：一段一段、一層一層、每層再切細條，高低亮度都不同，層跟層之間露出暗縫，角上岔出幾撮。
- **從預覽角度會被擋住的東西要換邊放**：倉庫左門往外開，擋住門內左半邊，草捆移到右半邊才看得到。

## 植被量產（`blender/grove.py` 26 輪、`blender/flora.py` 13 輪，2026-09-30）

參考圖 `docs/image/tree_list.png`（六種樹，闊葉樹已有）和 `docs/image/plante.png`（左兩區：仙人掌、荒草叢；右邊的木牌不是植被，沒做）。
兩支同時迭代、兩個審查子代理各審一支（定案 `docs/image/final/grove_v26_對照.png`、`flora_v13_對照.png`），預覽照參考圖的位置和高度擺（1 像素 = 1 公分），方便量。
進遊戲：有碰撞的（新樹、柱狀仙人掌）寫進 `levels/ranch.tscn`（`tools/plant_flora.gd`：舊松樹全換新的、森林和農莊換一些楓樹柳樹、
城鎮店面後面種仙人掌和荒漠樹）；草叢、小仙人掌、灌木沒碰撞，開場用 MultiMesh 撒（`main.gd` 的 `_flora_field`）。

**教訓**

- **彎的管子要用平行移動接每一圈的方向。** tree.py 的 `frame()` 在方向接近垂直時會換參考軸，彎的樹幹經過那個角度整圈會轉一下，
  擰出一圈皺褶（看起來像疊了一層布、或根部一塊浮板）。grove.py 的 `limb()` 改成每圈拿上一圈的軸投影過來。
- **「看起來像短刺」可能是方向問題不是長度問題。** 枯樹的側枝本來夠長，朝著鏡頭所以看起來短；限制成往上仰 50~70 度就解決。
- **審查者給的數字要先量過再照做。** 楓樹寬度、柳樹的「實心圓丘露出來」都是審查者自己後來收回的；照字面做出來像帽子、寶塔的，
  自己先看圖、跟它說明做法，它會更正目標。讓它「用量的」（二值化算透空比例、量像素寬高比）之後，意見就不再來回。
- **條件寫錯會讓整批東西不見。** 仙人掌的刺用 `i % 1 == 1` 永遠不成立，兩版都沒刺；審查者放大才發現。改了東西沒出現，先查程式。
- **雙面材質**：Blender 預設不剔背面，glTF 匯出 doubleSided，Godot 也兩面都畫，所以一片葉子兩個三角形就夠，不用做正反兩層。
  但背光那面會暗，葉面法線朝上比較好看。
- **headless 的工具腳本裡節點不在場景樹**，`global_position` 會回傳原點（而且只印錯誤不中斷）。`tools/plant_flora.gd` 自己把父節點的位移乘上去。

### 葉子改成葉片卡（grove v27~v55，2026-10-01）

使用者看了多面體葉團的定案版說「葉子不像，樹幹可以」，葉子改成**葉片卡**：兩片交叉的平面，貼透明底的葉子圖
（`tools/make_leaf_card.py` 用程式畫：楓葉、橡樹葉、松針、柳條、約書亞樹的放射尖葉，每片葉子左右兩半一亮一暗）。
工具在 tree.py（`card_material`、`card`、`ribbon`、`core`、`on_core`、`apply_card_normals`），闊葉樹也換了。
定案 `docs/image/final/grove_v55_葉片卡_對照.png`。

- **每團葉子要有暗色實心的芯**，卡片貼著芯的表面、再往外推一點：不然一團團的讀感出不來、團裡透空。芯要小（卡片的 45%），
  露太多又會變回「多面體球沾一層毛邊」。
- **法線從團中心往外**（存在點的屬性 `lnorm`，最後設成自訂法線）：整團像一顆球受光，不會每片卡各自一個亮暗、變雜訊。
- **葉片不接收影子**（Godot `disable_receive_shadows`，預覽裡樹不投影子）：不然一層層卡片互遮，樹冠裡面全黑。
- 預覽渲染要把透明穿透次數調高（`transparent_max_bounces`），預設 8 層穿不過去也會變黑。
- 貼圖透明處的底色填葉子的顏色，不然縮圖時黑邊滲進葉子邊緣。
- 合併物件（樹幹＋葉子）後要把貼圖座標設成渲染用的那組，不然整張取到透明角落、葉子全消失。
- 審查者給的輪廓數字一開始是目測的（松樹寬度偏窄一大截，松樹一直像毛柱的原因），讓它二值化實量參考圖之後才對。
  團數少的樹，單一高度的寬度會跳，量一段範圍的平均。

## 精修暴龍（`blender/trex_hd.py`，16 輪）

參考圖 `docs/image/dinosaur.png`（概念設計稿）。一整張連續的皮＋47 根骨頭的骨架（蒙皮），取代舊版 18 塊剛體零件。
一輪：`tools/trex_hd_iter.sh <版號>` → 五個視角排成參考圖的版面＋**疊圖**（我們的輪廓描在參考圖正面、側面上，同比例尺）。
局部特寫：`tools/trex_hd_close.py`。預覽擺成參考圖的姿勢（張嘴、側面跨步）才比得了。

**新的教訓**

- **疊圖比對照圖準。** 比例從參考圖側面量（像素 → 單位），疊圖一眼看出哪裡胖瘦；審查也改用疊圖量數字。
- **預覽姿勢自己的錯會被當成模型的錯。** v6 骨盆多轉 3 度，整隻前傾，審查連提了「胸太高、尾太高、頭太低」三點，其實模型沒錯。
- **管子沿彎道 loft 要平行移動斷面**，每圈重選上方向會在轉彎處整圈翻面，前臂被體素重建吃掉（v2 手斷掉）。
- **刀削感**：體素重建後減面會留下細長碎片；改 QuadriFlow 長均勻四邊形（要先合併重複點、統一法線，不然它說「不是封閉網格」直接取消）
  → 每個四邊形隨機挑對角線（對角線一致會排成橫紋）→ 頂點用**低頻雜訊**推（相鄰面合成大切面）＋一點每頂點亂推（才有折角）。
  每頂點亂推太大＝揉過的錫箔紙；顏色每面亂跳＝撒亮粉。顏色也要低頻成片。
- **稜線**：每個三角面三角標重心座標（面角色屬性 → glTF 頂點色），著色器取最小分量畫邊；線色用該面本身顏色壓暗，不要固定灰。
- **上色靠法線朝向會被「看得到的角度」騙**：背面看得到大腿後側垂直面、往上翹的尾巴下側，都被當成腹面上了米白。朝後的面要另外處理。
- **使用者的比例指示優先於參考圖**（「頭小一些、大腿小一點」），要轉告審查者當成新的固定目標，不然它會一直要求改回去。

**第二階段：使用者要「減少多邊形、更加俐落」（v17~v21，5282 → 1810 三角面）**

- 定版約 1800 面（審查判斷下限約 1500，再少大腿、胸口、尾根會變方塊、頭會失去眉骨）。分配：皮約 1100、下顎 240、牙 22 根、爪 12 根、刺約 35 根。
- 減面後最雜的是**小零件太多**，不是皮：刺 70 → 35 根（只留中線一排＋肩到髖的內側兩排）、冠刺改每側 2 根、牙上 6 下 5。
- 減面會把頭的起伏抹平（頭變磚塊）：眉骨要在斷面表裡刻意抬高、吻端上緣斜切；頭部斷面指數降到 2.3~2.5，正面才是山形不是平頂。
- 唇線在少面數下會變鈍，沿唇線放的牙會被埋進皮裡，要往外、往下移。
- 冠刺放在頭寬外側，正面看像貓耳；靠中線、往後倒 55 度才對。頭頂的刺要在頭關節以前，蒙皮權重才跟著頭走。
- 進遊戲：預覽用節點畫的稜線會讓 glTF 讀不到底色（整隻變白），匯出前拆掉；畫稜線用的頂點色也不匯出。
