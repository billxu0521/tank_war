# 效能

## 怎麼量

```
PERF=3 godot --path . --disable-vsync --resolution 1920x1080 --script tools/style_shots.gd
```

開沙盒，跟風格檢查同樣的 15 個角度（`tools/style_shots.gd`），每個停 `PERF` 秒（前 0.5 秒不算），關垂直同步、不限幀率。印兩行：

- 幀時間（平均、最慢 1%、最慢）、腳本、物理、繪製指令（draw call，叫顯示卡畫一樣東西一次）、三角形
- **畫面和影子分開**的繪製指令和三角形

開發機（Apple M5 Pro）每秒約 250 張，幀時間被雜訊蓋住，**看不出改動有沒有用**。所以比的是繪製指令和三角形——
這兩個在弱一點的電腦（隊友的 Windows 筆電、內顯）上才是負擔。GPU 時間在 Metal 上讀不到（一直是 0）。

清點場上每種模型的數量和三角形：`tools/census.gd`（見最後）。

   房子印 2 萬、預算 2.5 萬照過，匯出其實 8 萬。改成算匯出後真正的三角形
4. 美術那輪關掉了油畫筆觸（Kuwahara，全畫面每個像素取 8 塊扇形 × 半徑 7 的鄰居），順便省掉最重的一道全畫面效果

試過、更糟、退回：

- **把一樣的擺設手動合成 MultiMesh**：畫面繪製指令 493 → 656。引擎（Forward+）本來就會把同一個網格的東西合成一次畫，
  手動合反而打斷它，又少了逐個略過畫面外的
- **撒滿全場的樹、草叢分塊**：影子三角形少兩成，畫面繪製指令卻 493 → 960
- **遠景的樹換成匯入時的簡化版**：畫面三角形反而變多。引擎本來就會自動換簡化版（LOD），自己做的網格沒有多層簡化

沒動：

- 物理每秒 120 次：是為了修移動殘影特地拉高的（`docs/流程/驗證標準.md`），物理一幀不到 1 毫秒
- 開場第一眼會頓一下（最慢一幀 17～33 毫秒）：第一次畫到某種材質時在準備它，之後就不會

## 2026-11-16 主機每秒頓一下、小恐龍（腳本時間）

規劃見 [未完成事項](../企劃/2026-11-16-未完成事項.md) 第 3、4 項。量法：`SEED=1 ROUNDS=40 godot --headless --fixed-fps 60 --path . --script tools/bot_sim.gd`（一次只跑一個 Godot）。

注意：bot_sim 印的「每幀腳本時間」來自 `Performance.TIME_PROCESS`／`TIME_PHYSICS_PROCESS`，Godot **每一秒（實際時間）才更新一次，值是那一秒裡最慢的一幀**。bot_sim 快轉（實際一秒約 1000 幀），所以平均和最慢 1% 其實是「每 1000 幀裡最慢那幀」的分布，只能前後比，不是一般幀的成本。要看某個函式就直接量它（`Time.get_ticks_usec()` 前後相減）。

| | 改前 | 改後 |
|---|---|---|
| `party_hud.refresh()` 狀態沒變（每秒 `_sync` 那次） | 1271 微秒 | 0.6 微秒 |
| bot_sim 40 回合：每幀腳本時間平均 | 9.01 毫秒 | 6.96 毫秒 |
| bot_sim 40 回合：最慢 1% | 58.8 毫秒 | 41.9 毫秒 |
| bot_sim 40 回合：實際時間每幀 | 0.94 毫秒 | 0.82 毫秒 |

做了：

1. `party_hud.gd` 的 `refresh()`：會顯示的東西（階段、分數、本回合分數、名字、誰是恐龍、結果文字、誰拿蛋、誰拿星星）算成雜湊值，跟上次一樣就不重建。主機和玩家都受惠
2. `cowboy/viewmodel.gd`：沒拿在手上的槍 `set_process(false)`，換槍時開回來（一個牛仔 11 把）

還沒做：

- **專用伺服器不算尼諾拉骨架**（`trex.gd` 的 `_process`，平常一幀最貴的一塊，約 141 微秒）：`boss.head_position()` 讀頭骨位置判爆頭，跳過要改用固定頭高（`_head()`），專用伺服器上打頭的位置會跟畫面差一點。主機重開後還頓再做
- **主機重開後補驗**：1 人＋3 電腦，記錄裡「主機停頓」不再每秒一行（主機關著，現在驗不了）
