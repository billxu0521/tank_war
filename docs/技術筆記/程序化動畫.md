# 程序化動畫筆記

來源：[Procedural Animation is EASY](https://www.youtube.com/watch?v=7yXqfESL5qo)

不預先做關鍵影格，直接用程式算出生物的動作。核心是三招。

---

## 為什麼要這樣做

傳統做法要為多足生物準備「各個方向 × 各種速度」的動畫組合，再寫一堆狀態機轉場邏輯把它們接起來。
數量是相乘的，很快就爆炸。

程式化動畫在執行時依物理和環境即時算，不需要窮舉。

**但不是要取代關鍵影格。** 兩者混用最好：關鍵影格給你控制力（招式、演出），
程式化給你動態反應（慣性、地形、速度）。

---

## 第 1 招：旋轉延遲傳遞

**原理**：骨鏈的第一節跟著某個來源轉，之後每一節每幀先重設，再「部分追隨」前一節**上一幀**的角度。

- 追不上前一節 → **延遲**
- 追過頭 → **過衝**，也就是彈性

**用在哪**：尾巴、脖子、軀幹。頭一轉，尾巴就會甩出去再回彈。

**實作**（本專案 `trex.gd` 的 `_propagate()`）：每一節用一個彈簧–阻尼去追目標角度。

```gdscript
func _propagate(ang, vel, driver, stiff, damp, delta):
	var prev = ang.duplicate()          # 一定要用上一幀的值，不然會瞬間傳到底
	for i in ang.size():
		var target = driver if i == 0 else prev[i - 1]
		vel[i] += (target - ang[i]) * stiff * delta
		vel[i] *= exp(-damp * delta)    # 這樣寫才跟幀率無關
		ang[i] += vel[i] * delta
```

兩個旋鈕：
- `stiff` 越大追得越緊，延遲越短
- `damp` 越小晃越久，過衝越明顯

**驅動來源**要選對。本專案用「身體這一幀轉了多快」：

```gdscript
var yaw_rate = wrapf(yaw - _yaw_prev, -PI, PI) / delta
var driver = clampf(-yaw_rate * 0.20, -0.65, 0.65)   # 負號 = 往反方向甩，這就是慣性
```

實測本專案的暴龍（4 節尾巴）：

| 時機 | 尾巴根 | 尾巴尖 |
|---|---|---|
| 轉身當下 | −0.34 | −0.00 ← 完全跟不上，這就是延遲 |
| 停止轉身後 | ≈0 | +0.30 ← 反向甩過頭，這就是過衝 |
| 再過幾秒 | 0 | 0 ← 收斂 |

## 第 2 招：圓周運動 + IK 解算

**原理**：腳的 IK 目標掛在一個旋轉的圓上，圓周走完一圈就是一個步伐。各隻腳的**相位錯開**。

**關鍵細節**：
- 圓周的旋轉速度跟角色移動速度掛鉤 → 走多快腳就動多快，不用做多套動畫
- 配**射線檢測**把目標壓到地面，就不會穿地，上下坡也自動貼合
- 離開地面時，把整個圓軌往**後上方**移動 → 動作自然變成划水，可以直接拿來當游泳

**本專案的做法**：腳有 IK（`trex.gd` `_walk()`），但目標不是繞圓軌，是「支撐期釘在世界座標、擺動期畫弧到下一個落點」，相位跟著走過的距離。

---

## 第 3 招：位置平移延遲

**原理**：第 1 招是對「旋轉」做延遲，這招是對「位置」做同樣的事——
末端目標（前肢、頭）的位置也用彈簧去追它該在的地方。

**效果**：身體移動時肢體慢半拍地跟上，產生重量感。

## 改走路動作前要知道的（2026-11-11 修抖動時量出來的）

- **模型跟「畫面上的」身體走，不跟物理步的身體**：`trex.gd` 的 `_follow()` 每幀把模型擺到物理插值補過的身體上（模型是 top_level、自己不經過物理插值）。身體一秒 120 個物理步，畫面幀率對不上（50 張、不鎖幀）時，用物理步的位置算速度會每幀忽快忽慢，釘在世界座標的腳也對不上畫出來的身體。要動模型相對身體的位置改 `_seat`／`down_roll`，不要改 `$Trex.transform`（每幀被蓋掉）。
- **腳用沒平滑的速度、身體用平滑過的**：步伐相位要跟實際走過的距離一致，平滑過的慢半拍、起跑時腳被拖在後面；點頭、側傾、位移延遲這些「速度變了多少」的衝量要平滑，不然客戶端（位置是一包一包補的）每幀被亂踢。
- **步伐的判斷用「沒扭、沒左右移」的骨架座標**（`_walk()` 的 `sk_xf`）：骨盆扭、重心左右移是表演，算進去踩著的腳會被當成偏太多、提早抬或往旁邊滑。新加的全身動作如果會移動骨架，也要從這裡扣掉。
- **尼諾拉的腳不踩積木和碎塊**（`_ground()` 的 `_big`）：牠站不上去，射線打到腳邊的半面牆、碎塊，腳會一幀跳上牆頂。小恐龍照舊踩得上去。
- **打擊停頓（hitstop）時腳踩的地方要跟著身體搬**：骨架凍住、身體沒停，不搬的話醒來那一幀腳跳回原地。
- **尾巴走路的波直接照步伐相位算**（`_tail_yaw_at()`），不走彈簧鏈：彈簧鏈在走路的頻率每節晚 70 度，八節左右互相抵銷，看不出在擺。彈簧鏈留給轉身甩尾。
- **客戶端補別人的位置要用微秒的鐘**（`fighter.gd` `net_step`）：整數毫秒在一幀 16 毫秒時有 ±6% 的誤差，補出來忽快忽慢。
- 量抖動：`tools/gait_probe.gd`（每張畫面量踩著的腳、頭、尾、骨頭有沒有來回跳；`FPS=50`／`120`、開視窗、`PROBE=tools/gait_probe.gd tools/jitter_probe.sh` 當客戶端）。拍連續畫面：`tools/gait_shots.gd`。走路檢查（`trex_walk_check`）是每幀直接搬架子，量不到物理步和畫面對不上的問題。
- 對照圖：`docs/image/尼諾拉走路_修正前後.png`、`docs/image/尼諾拉走路_修正前後.mp4`（走 → 跑 → 邊跑邊轉；左修正前、右修正後；上側面、下後上方）。

驗證方式：`godot --headless --script test_battle.gd`，
案例 `_case_trex_rig()` 會檢查「轉身時尾尖落後根部」和「停下後反向過衝再收斂」。
