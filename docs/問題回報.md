# 問題回報（bug 收集器）

> 2026-10-01 加入，v0.8.5 之後的版本都有。程式在 `bug_report.gd`，接進遊戲的部分在 `main.gd` 的「問題回報」段落。

## 一句話

**玩家按 F8，遊戲把錯誤和當時狀況整理成一份文字報告，存檔＋複製到剪貼簿，玩家貼到 Discord 那一版的討論串。**

## 玩家怎麼用

- **F8**（大廳、遊戲中都能按），或 Esc 選單的「回報問題（F8）」。
- 遊戲記到錯誤時，畫面下方的狀態列會跳「遊戲記到一個錯誤，按 F8 存成回報檔」。
- 存好後狀態列顯示檔案位置，內容已在剪貼簿，直接貼到 Discord，再補一句「當時在做什麼」。
- 給玩家的說明寫在 `說明.txt` 的【遇到問題怎麼回報】。

## 報告裡有什麼

| 段落 | 內容 |
|---|---|
| 開頭 | 版本（`project.godot` 的 `config/version`）、時間、作業系統、顯示卡、語系 |
| 遊戲 | 在大廳／哪個模式（單人打恐龍、沙盒、靶場、搶蛋……）、當牛仔／恐龍／觀戰、離線／主機／專用伺服器／連線編號、場上幾個角色 |
| 開了多久 | 遊戲開啟到按 F8 的時間，對照錯誤的時間戳 |
| 錯誤 | 每種錯誤只記一次、算次數，附第一次出現的時間和程式的呼叫順序（backtrace）。最多 30 種 |
| 最近紀錄 | 最近 200 行遊戲印出的訊息（含警告） |
| 結尾 | Godot 完整紀錄檔的資料夾（當掉時用） |

**警告不算錯誤**：只進「最近紀錄」，不跳提示（導航網格每局都會印兩行警告）。

## 存在哪裡

- 報告：`user://bug_reports/OvD_<日期>_<時間>.txt`
- 遊戲當掉時沒機會按 F8，改看 Godot 自己的紀錄：`user://logs/`（最新一個檔）
- `user://` 實際位置：
  - Windows：`%APPDATA%\Godot\app_userdata\Outlaws vs Dinosaurs 法外狂徒大戰恐龍\`
  - macOS：`~/Library/Application Support/Godot/app_userdata/Outlaws vs Dinosaurs 法外狂徒大戰恐龍/`
  - 遊戲名稱改了，這個資料夾名稱也會跟著變

## 怎麼運作

- `BugReport` 繼承 Godot 的 `Logger`，開場由 `main.gd` 呼叫 `BugReport.install()` 掛上（`OS.add_logger`，只掛一次）。
  之後 Godot 印出的訊息、`push_error`、引擎錯誤、腳本錯誤都會經過它。
- 記錄可能從別的執行緒進來，所以都包在 mutex 裡。畫面提示由 `main.gd` 的 `_process` 每幀問 `take_new_error()`。
- 收集器自己不能 `print`，不然會自己記自己。

## 改的時候要注意

- **換版號要改兩個地方**：`export_presets.cfg` 的 `application/version` 和 `project.godot` 的 `config/version`。
  不一樣的話自我檢查（`_case_bug_report`）會擋下來，不然報告上的版本會是錯的。
- **新增遊戲模式或角色**：`main.gd` 的 `_game_state()` 要補上，報告才看得出玩家在玩什麼。
- 自我檢查 `_case_bug_report` 驗：錯誤會記、警告不算、同一個錯誤只記一次、F8 存得出檔、內容有版本／錯誤／遊戲狀況、版號兩邊一致。

## 讀回報（給開發的人）

1. 先看**版本**：回報講的是哪一版，就對那一版的程式看，最新版可能已經改了。
2. 看**錯誤**段的檔名和行號、呼叫順序，對到程式。
3. 對**時間戳**：錯誤第一次出現的時間，往「最近紀錄」找那附近發生了什麼。
4. 看**遊戲**那行：連線中的客戶端和主機跑的程式不一樣（恐龍、傷害都在主機算），要分開看。

## 還沒做的

- **自動上傳**：在 `save()` 之後用 `HTTPRequest` 送到 Discord webhook 就能自動進討論串。
  但 webhook 網址放在遊戲裡等於公開，任何人都能拿去灌訊息，要先想好怎麼防再做。
- 玩家在遊戲裡打一段說明（`build()` 已經留了 `note` 參數，缺輸入框）。
