1. Structure 識別結構

Version 0.4 · October 19, 2026 · Draft for Review

本規則適用於環境模型、構件、材質、表面圖樣與組合，統一資產身分、可重用配置及地圖引用。資產內容查製作目錄，製作與驗收依交接準則。

資產碼：PRP-0001。配置碼：PRP-0001_V00_L00_CRMC_CD-GBB。

讀法為「資產＿形體變體＿材質搭配＿組織客製＿地域風格」。底線分隔五欄，連字號保留在欄位內。此格式用於可放入場景的模型／組合配置；MAT、DEC 等被引用資源使用自己的穩定資產碼與修訂，不硬套五欄。

Table 1. 固定欄位與預設值

欄位 示例 預設值及範圍
資產 PRP-0001 必填；三字母分類＋四位流水號
形體變體 V01 V00 為基準形體；按各資產查表
材質搭配 L01 L00 為基準搭配；L 取自 Look，按各資產查表
組織客製 CRMC NONE 表示無組織客製；不表示無主
地域風格 CD-GBB STD 表示不再加入地域調整，保留前面已選內容

V00、L00、NONE、STD 都是有效且需有定義的值。TBD 表示尚未決定，只可留在需求草稿，不能當成完成配置。完整碼不省略中間欄位。地域風格描述外觀方案的來源，不等於目前放置地點；同一考爾德木箱可由多張圖引用。

基礎資產碼描述製作單位；完整配置碼描述一個可辨識的選用組合。編號登錄不代表模型已製作完成。V00、L00 須有該資產的實際形體與部位搭配定義，不能用預設字串代替缺漏資料。

2. Geometry and Materials 模型與材質

模型負責形狀、尺寸與表面分區；材質負責這些表面的顏色、粗糙度及其他表現。材質搭配則記錄「哪個部位使用哪份材質」，因此一個模型可以配多套材質，一套材質也可以被不同模型引用。Godot 提供模型實例與分表面材質覆寫，支持這種分工；交付配置仍須核對實際匯入結果。¹

Table 2. 同箱體的兩套材質搭配示例

搭配 BODY 箱板 HARDWARE 鐵件 引用模型
L00 未塗裝 Unpainted MAT-0001 舊木 MAT-0002 暗鐵 PRP-0001 的 V00
L01 塗漆 Painted MAT-0003 塗漆木面 同一 MAT-0002 同一 PRP-0001 的 V00

L00／L01 是該資產的材質搭配表，不是新的模型或一張貼圖。MAT 是可重用材質資源；所依賴的貼圖、遮罩、著色器與參數需列路徑、版本及來源，初期不另替每張圖片增加一層資產碼。各模型材質區域使用穩定名稱，匯入時再核對其實際表面索引，不能只假定「第 0 面永遠是木頭」。

相容性需檢查。 包含貼圖座標、紋理尺度、表面分區、透明／雙面需求及辨識標記的位置。特定模型烘焙出的法線或遮罩不應直接當所有模型通用。材質替換若需要不同 UV 排列，需補相容配置或來源變體；不只因外形相同就認定可直接換。²

微小色差、粗糙度調整不必各造新 MAT；在搭配表保存具體參數。需要長期獨立重用、可並存且具獨立表面意義的材質才另登錄。單純修正同一材質則增加修訂，不假裝是新的選項。

換木紋不改 V；側板缺失、增加有厚度的鐵箍等改變幾何的需求，選相容 V 或引用獨立構件。材質可以改善裂紋表現，但不能因此宣稱輪廓、通孔或碰撞已改好。修改共用材質時也要檢查其他引用者，局部效果不得無聲改掉所有箱子。

3. Categories 分類與衝突處理

Table 3. 七類資產及邊界

碼 名稱 收錄範圍與邊界
VEG Vegetation 植被 草、樹、灌叢及普通枯木形體；成群草叢仍可是一個 VEG 資產
PRP Prop 道具物件 箱、桶、工具、文件、車輛等有完整用途的物件
MOD Module 組裝構件 反覆拼裝的板、柱、框及牆段；MOD 不指全部模型
NAT Natural Forms 自然形體 岩塊、石化木、骨片等非普通植被自然形體

DEC Decal 表面圖樣 可獨立重用的表面標記／圖樣；具體以投射、貼面或其他方式實作另記
ASM Assembly 組合 有獨立重用價值、需保存子資產引用與相對配置的組合

Table 4. 分類邊界案例

容易重疊的情況 登錄方式
一只木箱由多片板組成 整箱仍 PRP；被獨立重用的板另為 MOD。物件內有多個 mesh 不自動變 ASM。
多只箱子組成可反覆擺放的貨堆 若需保留各箱引用與排法，登錄 ASM；只在一處隨手擺放則留地圖配置。
完整棚架／可重用建築外殼 需獨立管理構件組裝者為 ASM；場內那棟建物仍有 BLD 身分。
枯木、石化木與人工木料 普通枯木 VEG；石化木 NAT；切製組裝木料 MOD。木面材質另為 MAT。
植被、落屑可能用幾何，也可能用表面效果 先確定製作方式；形體依內容分類，純表面覆層為 DEC／MAT。不因植物題材把所有檔案都塞入 VEG。
標誌貼在箱上／掛一塊實體牌 表面圖樣 DEC；有厚度且需單獨製作的牌為 PRP／MOD，依用途選定，不重複登錄同件。
土面、坡地、裂縫 表面材質 MAT；可重用地形形塊 NAT；實際高程／分區屬地圖；模型裂口與表面裂紋分開。

類別依「這筆登錄實際交付什麼」決定，允許以組成關係連接不同類別，不把關聯誤當衝突。一筆資產只有一個主要類別；組織、異常性、地域及真實／虛構屬屬性。既有編號不因臨時用途改變而重發。

七類僅涵蓋環境製作，不擴及角色、動畫與聲音。無法合理歸類的新交付物才增類；一筆資產一個主要類別，名稱、用途與組成關係隨碼登錄。已發布的識別碼不重新指派給另一件資產。

4. Variants and Composition 變體與組成

Table 5. 同資產配置示例

配置碼 所選內容
PRP-0001_V00_L00_NONE_STD 基準箱體、未塗裝搭配、無組織客製、無地域調整
PRP-0001_V00_L01_NONE_STD 同箱體改為塗漆搭配，模型不複製
PRP-0001_V00_L00_CRMC_STD 可跨圖引用的考爾德箱子
PRP-0001_V00_L00_CRMC_CD-GBB 同一考爾德箱子，加上 GBB 外觀調整
PRP-0001_V01_L00_CRMC_CD-GBB 改用開蓋形體；其內面必須支援指定搭配

V、L 都以各資產為範圍，V01／L01 不在全庫表示同一種變化。資產名稱採中英對照；變體與方案表列明差異及相容項；未登錄的組合不能僅憑碼型正確就判定可用。V01 的開蓋可以是靜態外形，本規則不自動定義互動行為。

組織方案 CRMC 記錄辨識圖樣、指定顏色及必要配件；地域方案記錄可重用的塵土、色調或濕潤差異。它們引用 L／MAT／DEC 或相容構件，不各複製整套模型。組織成員的私人物件與受託找回的客戶物件，不因相關委託便加上組織標記。

若同一組織有兩種互斥的客製方案，可在該欄使用登錄過的 CRMC-02；地域也可有 CD-GBB-02。不另加第六欄或以連續底線省略。無尾號的方案定義後保持其身分；修正沿修訂管理，不將同一代碼同時解讀成兩個互斥方案。

每一組完整碼及其配置修訂，必須指向一份明確的組成清單。 清單固定所用模型修訂、各部位材質修訂、組織圖樣、地域差異及允許的參數範圍。層次順序便於閱讀，不是「最後者任意覆蓋」；必要標記與功能界面須受保護。若兩層都要改同一參數，需明定哪個生效或標不相容；不得悄悄忽略其中一層。

L00 不代表沒有材質，STD 不清除 CRMC，NONE 不清除材質。材質搭配與組織／地域方案的資訊不可重複定義在兩處：一般底材在 L，組織差異在組織方案，當地差異在地域方案，最終配置保存確定引用。

完整配置的登錄欄位見第 6 節；目錄中的配置是製作要求，實作後填入可讀回的來源路徑及修訂，才可標為已完成配置。

地圖網格 A1 等只負責定位。散布植物可以記分區、密度、排除區及配置來源，不逐株編 INS。單件的移動、旋轉與允許的縮放也不一定需要新配置碼；需要獨立重用、相互比較的設計選項才登錄。

修訂與變體分開：V01、L01 是可並存的選擇；r003 是某份來源或配置的修正歷程。已核可配置固定依賴版本，資產變動不使所有地圖無聲跟隨最新。

檔名採英文與半形數字，底線分詞；來源封存可加修訂尾碼，工程中的穩定匯出路徑不因每次修訂而任意更名。沿既有工程穩定路徑與 UID 規則，來源歷程另保存。不同外觀不應為了湊完整檔名而各複製一份相同模型；自包含交付需要打包時，列明來源及依賴。

登錄需保留作者／來源與使用條件、檔案路徑、適用範圍、製作與核可狀態。以現有物件表銜接正式生產，不另設兩份競爭的權威清單。各地圖另記資產的採用範圍；能重用的模型不代表其異常設定也自動適用其他地圖。

BLD、LOC、ZON、RTE 在各圖、各類別內獨立起編，以兩位數起列；INS 以三位數起列。移位或同一項目的尺寸調整不換碼；拆成不同項目或合併成新項目時另編。停用碼不回收；超出原位數時擴位，不重排既有號碼。已公開引用的身分若變更，在獨立修訂紀錄列明受影響項目。

6. Registration 登錄與依賴

資產目錄管理製作單位與設計定義；專案物件表管理製作狀態與認領。兩者以資產碼連結，不另維護互相競爭的完成狀態。

Table 8. 資產與配置的必要紀錄

紀錄 必填內容
資產 穩定 ID、中英文名稱、用途、形態／尺寸範圍、類別、來源與使用條件。
形體 V 所屬資產、形體差異、尺寸、局部原點與方向、可拆件、材質部位；完成後填來源修訂。
搭配 L 所屬資產、各部位對應的 MAT／DEC、參數及可用 V；明記 UV 或遮罩限制。
組織／地域方案 登錄鍵、適用資產、標記或外觀差異、引用資源、保護部位及衝突處理。
完整配置 五欄碼、配置修訂、各層引用、最終部位搭配、允許參數及相容性結果；完成後填檔案路徑。
ASM 組合 子資產配置與修訂、相對變換、接點及可變範圍；引用不得形成循環。
地圖實例／散布 配置與修訂、BLD／LOC／ZON／RTE 參照、位置／朝向／尺度，或散布範圍、密度及排除區。

6.1 Registration Checks 登錄檢查

  1. 先查既有製作單位；能用搭配、形體或配置表達差異時，沿用基礎 ID。
  2. 檢查 ID 唯一、各欄已登錄、依賴存在、組合無循環，並確認所選形體具有需要的材質部位。
  3. 組織與地域若修改同一參數，記錄明確合成方式；無法同時成立的組合標為不相容。
  4. 完成資產時鎖定來源、匯出與依賴修訂，依製作準則讀回驗證。依賴更新時列受影響的配置，不讓所有地圖自動跟隨最新檔案。

尚未建立模型的目錄項仍可用來分工與估算；其配置定義、完成資產與遊戲內驗收是不同階段。

7. Test Assets 內部測試資產

TST 是內部測試的作用域前綴，置於既有類別之前；例如 TST-PRP-0001。它不是第八類資產，也不代表某張地圖。各類別的測試流水號獨立起編，不占用無前綴的常規資產號碼。

配置仍使用五欄：TST-PRP-0001_V00_L00_NONE_STD。整個 TST-PRP-0001 是第一欄；後四欄、空碼、形體／材質分工及相容性規則不變。TST 不授予任意匯入第三方素材的使用權。

7.1 Registration and Reuse 登錄與重用

測試資產登錄於製作目錄第 11 節，與常規項目清楚分組；條目、配置及組合均標記 internal_test。可重用既有 MAT 等資源，局部外觀調整保存在測試搭配，不能改寫共用底材。

地圖 BLD／LOC 引用套件並記錄實際位置。組合內以 INST-01 等局部名稱辨認子物件；它們只在該組合內唯一，不取代第 5 節的地圖 INS。移至別圖時沿用資產與組合碼，另記地圖落點。

7.2 Status and Release 狀態與發布

登錄不表示模型完成或已核可進入正式遊戲；製作狀態仍由專案物件表管理。文件可收錄測試項，正式遊戲資產打包需依採用清單選入，不因目錄存在便自動包含。

若測試成果日後成為常規資產，依其可重用製作單位登錄常規 ID，在獨立修訂紀錄保留來源關係，逐一更新採用者；不得直接去掉 TST 前綴後假定身分、來源條件或所有引用都已處理。
