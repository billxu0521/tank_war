1. Scope 文件分工

Version 0.3 · October 19, 2026 · Draft for Review

本準則用於環境資產的拆件、製作、組裝與交付。先確認地圖的用途與外觀，再選製作單位與配置，交付可追溯、可繼續編修的成果。

Table 1. 文件分工

文件 內容 查閱時機
地圖概述與製作規格 場所、配置、數量、地勢、開口、異常及本圖接面。 確認空間與使用條件。
編碼與組成規則 資產身分、分類、形體／搭配與組織／地域方案。 登錄、命名及重用。
環境資產製作目錄 製作單位、形態要求、材質、配置與查找關鍵字。 選件、拆件與估算。
本準則 製作摘要、接口、來源、匯出、交接與檢核。 開工至交付。

1.1 Work Units 工作單位

共用資產記物件本身的形狀、尺寸、材質部位、可拆件與使用限制；地圖配置記所用資產、搭接與落點，以及場所、地形和角色的關係。BLD／LOC 保留場所身分，所用梁柱、箱子或岩塊可跨場所重用。

1.2 Project Records 專案紀錄

正式製作沿用物件表與程式建模迭代。目錄提供設計定義，認領與完成狀態回接物件表。技術預算、引擎及匯出設定依實作任務的專案規範；地圖文件補充該圖的使用限制。

2. Work Brief 製作前交代

每個可獨立交付的物件或構件組，附一份簡短製作摘要。已在地圖規格寫清楚的內容，以連結引用，避免兩處各維護一份。

Table 2. 製作摘要的必要資訊

項目 寫法
識別與用途 資產碼、名稱、配置與修訂；說明是外殼、組裝構件、陳設或可互動部件
外觀依據 指定文件版本與條目；列出必須保留的輪廓、材料、年代／修補痕跡，附有辨識力的搜尋關鍵字
尺寸與範圍 用公尺記長、寬、高；分清外包尺寸與可通行淨空；指定設計目標值及容許調整範圍；量體驗證後回填實際尺寸
拆件與接點 指出哪些部分需獨立、由誰製作、接在哪裡；建物說明地基、牆、屋頂與開口的交接
材質與表面 列模型部位與材質搭配，說明共用底材、局部圖樣及磨耗差異；依編碼規則引用 MAT／DEC
行為與限制 可否開啟、行走、翻越或遮擋；將指定用途轉為碰撞與互動要求；仍需測試的部分標明通過條件
交付與審閱 製作者、審閱者、整合者；來源／匯出位置、代表檢查情境、依賴與待解事項

2.1 Modular Construction 構件組裝

  1. 先找可重用的構件，再決定新增單位。牆板、梁柱、門窗、屋面各自保留適合編修的來源；同一構件的尺寸規格與接合方式一併記錄。
  2. 門片、可動吊具與其他會獨立互動的部件，明確分離並標出轉軸或運動方向。純裝飾小件可成組製作，不要求逐顆釘子登錄。
  3. 場所特有的組裝記在 BLD／LOC 規格；可跨場所重用的組合才另考慮 ASM。構件完成不代表整棟空間已完成。
  4. 原始構件與引擎匯出可以有不同分組，但交付時保留對照。若匯出合併了幾何，仍需能回到可編修來源。

2.2 Visible Evidence 可製作的敘事

將「有人匆忙離開」轉為未收妥的工具、半裝貨箱與具方向的散落物；將異常轉為可看見的形態、材質、位置或已指定的簡單效果。背景理由留在設定參照，製作摘要聚焦實際需做的物件及狀態。

3. Assembly and Surfaces 組裝與表面

3.1 Interfaces 接合資訊

Table 3. 組裝時要對上的資訊

接合項目 交代方式
資產原點與方向 記長向、正面、上方向及原點用途；門片原點可在鉸鏈，落地物可在底面。以實際匯入流程核對座標轉換
構件模數與接縫 列相接的尺寸、端點及是否容許裁切／縮放；特殊轉角、斜頂與收邊須另有處理方式
開口與通行 記開口尺寸、門片開向、門檻與內外落差；淨高扣除梁、吊具及其他實際占位
接地與支承 指定埋入、坐落、懸空或支架的位置；地基、巨骨與岩塊須和地形一併核對，避免看似漂浮
地圖定位 配置記錄引用場所／分區、位置、朝向、比例及高度基準；資產局部原點與地圖 H 值分開記錄

地圖高程、洞頂與骨段支點等候選尺寸，先由量體確認，再回填來源。物件做得完整，不代表與地形接面已解決。

3.2 Geometry and Material 模型與材質

編碼範例 PRP-0001_V00_L00_CRMC_CD-GBB 依序表示資產、形體、材質搭配、組織客製及地域風格；完整定義與空碼見編碼規則。實際擺放位置另記。

Table 4. 變更時如何分工

變更內容 製作處理
同箱體換表面搭配 引用同一形體，列新的材質搭配；核對部位、木紋比例與圖樣方向
增加有厚度的鐵箍或破損缺口 評估形體變體或獨立附件；一併檢查碰撞需求
多物件使用同種木面 共用材質資源，各自保留部位對應；專用 UV 或烘焙遮罩須標相容範圍
同物件出現在另一地圖 新增配置引用；僅在外觀確有差異時選另一風格方案

每個交付配置固定引用的來源、材質與圖樣修訂。局部換色或風化先確認是否會修改其他物件共用的資源；碰撞、遮蔽與視覺表面分別核對。模型與材質的相容性以實際來源及匯入結果核對。

4. Delivery 交付內容

交付包讓接手者能辨識版本、打開來源，並在預定流程中重現結果。以下按資產用途選用；沒有必要的項目註明不適用。

Table 5. 交付包內容

內容 最少需要交代
可編修來源 來源檔與必要建模腳本、工具版本；保留構件及材質關係。只有生成結果、沒有可編修工程時如實註明
引擎用匯出 匯出檔、來源修訂、單位、軸向與匯出設定；若此階段只做來源，註明尚未匯出
依賴清單 使用的模型、材質、圖樣及各自修訂；提供實際檔案或可存取的專案相對路徑
組裝／配置資料 部件對應、原點、接點與允許變化；屬地圖配置時加場所／分區及高度基準
檢查證據 對應本次版本的必要視角、尺寸及測試結果；圖像依專案規範存於任務的 docs/image/
來源與條件 外部材料的提供者、網址／取得日期、使用條件與必要署名；自製、參考及直接取用分清楚
已知問題與回退 問題編號、影響、暫行處理、下一步；上一個可恢復版本的位置

4.1 Version Links 版本對應

同一交付的來源、匯出與檢查圖應指向同一修訂。保留前版；修補時列出受影響的下游配置。只改局部材質，也需讓接手者知道哪些物件會一起改變。

4.2 Ownership 分工紀錄

開工前查既有認領，再記錄本次檔案與製作者、審閱者、整合者；三者可兼任。共享腳本或二進位匯出檔的修改範圍須明確。認領須在團隊共用紀錄中確認，避免同時修改同一份二進位檔。

正式物件表仍使用「定案／可用／暫代／待做」。另在交付紀錄註明本次完成了哪種檢查；技術匯入成功不會自動升為視覺定案，視覺定案也不等同所有玩法與效能驗收完成。

5. Verification and Issues 驗證與問題管理

5.1 Review Stages 分階段檢查

Table 6. 檢查項目與通過界線

階段 確認重點 此階段不能代替
來源讀回 儲存後能重開；尺寸、部件、引用與修訂可對照 匯出正確或遊戲可用
匯出／匯入 匯出後再匯入，確認比例、方向、表面、活動部件及依賴 視覺方向核可
場景視讀 在代表地形與光線下檢查外觀、接地、開口、遮擋；必要時固定相機比較 角色實際通行與性能
遊戲驗證 用實際角色／恐龍及相機檢查通行、遮蔽、互動、碰撞；依用途檢查效能與多人行為 所有地圖與所有配置的全面驗收

每次只報告實際做過的檢查，標明版本、情境、結果與未驗項。製作初期先以代表性構件或場所驗證，再擴充；後續更改了相關條件，才重驗受影響部分。

5.2 Map Handoff 地圖專屬交接

地圖文件保留本圖量體順序、分工接面、代表樣本與局部檢核。例如哪段棧道須等骨段支點確定、哪處洞頂要核對外部地形、哪些植被區需放入角色驗證。共通材料與檔案規則引用本準則，不在每張地圖重寫。

5.3 Open Issues 實作待解事項

地圖文件末尾集中列待解項，使用固定項號，如 ISS-001。這是文件內的問題編號，與資產碼及網格分開；跨文件引用時附文件版本。

Table 7. 每項問題保留的欄位

欄位 內容
項號與位置 固定項號；關聯 BLD／LOC／ZON 或頁碼
問題與影響 哪裡未定、會阻擋哪些製作或造成哪些不一致
暫行處理 目前可依循的候選，或需先保留的空間
下一步與負責 需設計決定、補查、量體測試或遊戲驗證；標明由誰處理與應在哪一階段完成
狀態與結論 待處理／進行中／已決定待整合／已關閉；關閉時附決定及落實版本

已解決項保留簡短結論，不因關閉而重排項號。設計提案、審核問答與編修回饋另存獨立紀錄。地圖末尾只列會影響執行的條件、依賴與待驗項；決議後將結果寫回相關規格，避免要求製作者自行從討論串推斷。
